# QGIS-xtopo

Плагин QGIS, который готовит данные OpenStreetMap и рельефа для печатной
топографической карты и открывает их в виде проекта QGIS со стилями
`automap.qgz`.

Никаких Docker, внешних сервисов и ручной подготовки GeoPackage: всё
выполняется прямо в QGIS — от выбора области на карте до экспорта листа
атласа в PNG или PDF.

---

## Возможности

* **Подготовка данных OSM** из Geofabrik (по умолчанию), публичного Overpass
  API, локального PBF/OSM-экстракта, локального Overpass или Overpass по SSH.
* **Подбор карт Geofabrik** по текущему охвату: минимальный набор регионов
  (родительский регион не скачивается, если выбран потомок), проверка
  доступности карт в фоне, скачивание и склейка.
* **Рельеф**: SRTM-тайлы (с кэшем) или локальный каталог DEM, затенение и
  уклоны, контуры высот с выбором кратности (5, 10, 25, 50, 100, 200 м) и
  вырезанием контуров из водных поверхностей — постоянных и пересыхающих
  (`intermittent=yes`), отдельные изолинии по ледникам.
  Готовый рельеф и контуры не пересчитываются, пока не изменились версия
  плагина, параметры и исходные данные.
* **Обработка береговой линии** и океана.
* **Параллельная обработка** независимых слоёв, автоматическое удаление
  пустых слоёв из готового проекта.
* **Панель настроек проекта**: включение и выключение слоёв рельефа прямо в
  открытом проекте, привязка к слоям, инструменты «вписать карту в экран» и
  «прокрутка карты».
* **Атлас**: разметка листов прямо на карте, формат и ориентация листа,
  масштабная линейка, номер листа, копирайт OSM, экспорт в PNG/PDF и печать.

## Требования

* QGIS 3.28 или новее (проверено на QGIS 3.34).
* GDAL/OGR и Python из состава QGIS — дополнительных установок не требуется.
* Для Overpass API нужен доступ в интернет; для локальных режимов —
  собственный `osm3s_query` или файл `.pbf`/`.osm`.
* osmium-tool (поставляется с плагином, ставить отдельно не нужно) — нужен
  только для ускорения подготовки больших выгрузок, см. «Ускорение подготовки».

## Установка

1. Соберите архив (или возьмите готовый из `dist/`):

   ```sh
   python3 tools/build_plugin.py
   ```

2. Установите его в QGIS: **Плагины → Управление и установка плагинов →
   Установить из ZIP**. Либо одной командой в профиль QGIS:

   ```sh
   python3 tools/build_plugin.py --install
   ```

3. Включите плагин «QGIS-xtopo» и откройте его панель
   (меню **Вид → Панели → QGIS-xtopo**).

### Установка для новых пользователей одной командой

Сборка формирует готовый набор `dist/qgis-xtopo-ready/` (архив плагина +
лаунчер). Достаточно передать новому пользователю этот каталог: он запускает
`./install-and-run.sh`, и лаунчер сам ставит плагин в профиль QGIS, включает
его и открывает QGIS с готовой панелью. QGIS при этом должен быть закрыт.

Корень репозитория одновременно является корнем плагина: при установке
каталог называется `qgis_xtopo`, поэтому в архив файлы кладутся в каталог
`qgis_xtopo/`.

### Инсталлятор для Windows

Для Windows собирается настоящий установщик
`dist/qgis-xtopo-setup-<версия>.exe` (Inno Setup, исходники — в
`installer/`). Он:

* проверяет, установлен ли QGIS; если нет — предлагает скачать и
  установить официальный установщик QGIS (standalone MSI, около 1,5 ГБ);
* ставит плагин в профиль QGIS и включает его в `QGIS3.ini`;
* создаёт ярлык «QGIS-xtopo» на рабочем столе и в меню «Пуск»: ярлык
  запускает QGIS сразу с открытой панелью плагина;
* при удалении убирает плагин, ярлыки и запись в `QGIS3.ini`.

Установка идёт в профиль пользователя, права администратора не нужны.
Сборка: `installer/build-installer.sh` (Linux/macOS, через wine) или
`installer/build-installer.ps1` (Windows). Подробности — в
[installer/README.md](installer/README.md).

## Использование

### Вкладка «Данные»

| Поле | Назначение |
|------|------------|
| Каталог проектов | куда складывать подготовленные проекты |
| Имя проекта | буквы (латиница и кириллица), цифры и `_ - +` |
| Охват | `lon_min,lat_min,lon_max,lat_max` или ссылка OpenStreetMap; кнопка «Выбрать…» открывает карту, позволяет найти место по названию и нарисовать прямоугольник |
| Режим | Карты с Geofabrik (предпочтительно), публичный Overpass API, локальный PBF, локальный Overpass, Overpass по SSH |

При первом запуске охват пустой. Если нажать «Подготовить данные» без охвата,
плагин сам откроет окно «Выбор охвата карты» (в нём Enter применяет охват и
закрывает окно, а в строке поиска Enter запускает поиск места); если его
закрыть, подготовка не начнётся, а в строке состояния появится
«Охват не выбран».

В окне выбора охвата рамку можно задать мышью (кнопка с иконкой
прямоугольника), а рядом с каждой осью рамки показывается длина стороны в
километрах: по горизонтали — ширина, по вертикали — высота. Расстояния
считаются по эллипсоиду WGS84.

Кнопка «Открыть проект» доступна, только если файл проекта по указанным
каталогу и имени уже существует; панель по умолчанию открывается на
минимальную ширину, дальше её можно растянуть вручную.

При открытии подготовленного проекта плагин всегда скрывает лишние элементы
интерфейса QGIS — панели («Слои», «Браузер» и другие), все панели
инструментов и строку уведомлений над картой; на экране остаётся только
панель плагина. Кнопка со значком панели в строке состояния (рядом с кнопкой
журнала) переключает видимость: скрытое возвращает, видимое скрывает; при
закрытии проекта всё возвращается само.

Для режима Geofabrik плагин сам определяет нужные карты по охвату, показывает
их список с родительским регионом и объёмом, а по кнопке «Подготовить данные»
скачивает и склеивает их. Во время загрузки в строке состояния идёт общий
счётчик: процент, скачано/всего, число карт, текущая скорость и расчётное
время до конца (например,
`Загрузка карт: 42% (7.7/18.4 МБ) · 0/1 · 3.1 МБ/с · ~4 мин`). Длинная
строка переносится, высота строки статуса растёт, поэтому хвост с ETA не
обрезается.
Дата индекса Geofabrik показана в заголовке группы «Карты Geofabrik».
Карты, которые уже лежат в локальном кэше, подсвечены в списке зелёным
и помечены «скачана».
Карты крупнее 7 ГБ к скачиванию не предлагаются: они исключаются и из
списка, и из автоматического подбора.

Для публичного Overpass сервер проверяется фоновым тестовым запросом, его
доступность показывается в списке.

Запросы Overpass выполняются пакетами: простые фильтры по тегам объединяются
в несколько общих запросов, а ответ разбирается на слои на стороне клиента,
поэтому вместо 160 с лишним отдельных HTTP-запросов выполняется несколько.
Сложные запросы (например, с `->.relations`) выполняются как обычно. Ответы
кешируются по охвату и по тексту запроса: если запрос изменился, данные
скачиваются заново, а не берутся из старого кеша.

Режим PBF читает файл в два прохода: сначала грубый фильтр GDAL по области
(с небольшим запасом, чтобы объекты на границе пришли с целой геометрией),
затем точная проверка пересечения с самим охватом — в выход попадают только
нужные объекты. На файле в 500 МБ это сокращает время обработки примерно в
пятнадцать раз по сравнению с полным перебором (проверено на карте Северного
Кавказа: 3 200 объектов вместо 2 458 000, 3 с вместо 38 с, результат тот же).
В некоторых выгрузках индекс PBF битый, и фильтр драйвера отдаёт объекты из
другого места файла: такой фильтр плагин замечает и читает файл целиком,
иначе нужная область в вывод не попала бы.

Площадные дороги (`highway=*` с `area=yes` и `area:highway=*`) попадают в
слой «highway main area» и рисуются заливкой, как обычные дороги. В OSM они
заданы замкнутым контуром, который драйвер отдаёт линией, поэтому при
обработке замкнутые линии превращаются в полигоны. Подписи площадей и
площадных дорог выводятся слоем «place square highway area names».

Перед подготовкой каталог проекта очищается: прежние векторные и растровые
слои удаляются, чтобы в проекте не осталось данных от прошлого запуска.
Промежуточные файлы DEM (`merged_dem*`) при этом сохраняются — это кэш
репроекции, а не слои.

В конце подготовки в журнал выводится хронометраж: сколько времени заняли
этапы (источник OSM, обработка слоёв, береговая линия, рельеф, очистка) и
самые долгие операции. По нему видно, на что ушло время. Скачивание карт и
ответов Overpass считается отдельно («скачивание данных»), поэтому видно,
сколько времени ушло на сеть, а сколько — на разбор. Кнопка рядом с
галочкой «Журнал» открывает отдельное синхронизированное окно журнала.
Кнопка «Закрыть проект» доступна, когда открыт подготовленный проект.

Предупреждения GDAL не сыплются в консоль QGIS, а собираются в сводку в
конце журнала: сколько было незамкнутых колец в данных OSM, сколько объектов
с типом геометрии, не совпадающим с типом слоя. Причины двух типов важны:
незамкнутые кольца GDAL закрывает сам (это особенность данных OSM, а не
потеря данных), а объект с чужим типом геометрии рисуется не везде, поэтому
такие объекты отбрасываются при чтении PBF: у отношений с разнородными
членами GDAL собирает GEOMETRYCOLLECTION, в котором часть полигонов не имеет
ни одной точки.

Обработка слоёв идёт параллельно (до шести слоёв сразу). Скорость сильно
зависит от числа тегов у объектов: каждый тег OSM становится отдельным
атрибутом, и здание из Швейцарии приходит с двумя сотнями колонок, из
которых карта использует меньше сотни. Разбиение слоя по тегу `layer`
идёт напрямую через OGR, без промежуточного JSON, а запись в SQLite
выполняется одной транзакцией: с флагом `-skipfailures` GDAL коммитит
каждую геометрию отдельно и замедляется в пять раз.

Имена полей приводятся к уникальным без учёта регистра: SQLite не
различает `communication:5G` и `communication:5g`, и без этого слой с
такими тегами молча терялся.

### Вкладка «Слои»

Список запросов OSM с кнопками «Все», «Ничего», «По умолчанию». По умолчанию
`route_hiking` выключен: маршруты редко нужны, а relation с ними разбираются
дольше всех.

### Вкладка «Рельеф»

* «Обрабатывать рельеф» — построить затенение, уклоны и контуры.
* «Источник» — набор данных рельефа: SRTM v3 (skadi), Copernicus GLO-30,
  NASADEM, ALOS AW3D30, USGS 3DEP или свой каталог DEM. Под списком —
  краткая справка: провайдер, система высот, покрытие и доступность
  (число тайлов) для выбранного охвата; разрешение, примечания и
  атрибуция — в подсказке.
* Наборы, которых для охвата нет, в списке отключены: 3DEP — вне США,
  Канады и Мексики, NASADEM — за полярными широтами, GLO-30 — в Армении,
  Азербайджане, на северо-западе Ирана и в Туркменистане (25
  неопубликованных тайлов).
* Доступность проверяется сразу после выбора охвата, в фоне и до открытия
  вкладки «Рельеф». Если набор недоступен, панель сама переключается на
  подходящий. Если охват полностью покрыт 3DEP по суше (океан не
  учитывается), источник автоматически переключается на 3DEP. Выбор
  другого источника для такого охвата сопровождается предупреждением.
* «Свой каталог DEM» — тайлы `.tif/.hgt/.zip` с именами как у SRTM
  (`N42E044`). Поле каталога показывается только для этого источника.
* «Метод масштабирования» и горизонтальный разделитель.
* «Контуры высот» и кратности 5, 10, 25, 50, 100, 200 м: включение одной
  кратности автоматически включает все зависимые (например, 5 м включает
  10/25/50/100/200), несовместимые кратности (200 против 100 и 1000)
  исключаются.
* «Сглаживать контуры».

#### Источники рельефа

| Источник | Разрешение | Покрытие | Высоты |
|---|---|---|---|
| SRTM v3 (skadi, AWS) | 30 м | 56° ю.ш. – 60° с.ш. | EGM96 |
| Copernicus GLO-30 (ESA, AWS) | 30 м | суша; 25 тайлов не опубликованы | EGM2008 |
| NASADEM (NASA, Planetary Computer) | 30 м | 56° ю.ш. – 61° с.ш. | EGM96 |
| ALOS AW3D30 (JAXA, Planetary Computer) | 30 м | глобально, DSM | EGM2008 |
| USGS 3DEP (Planetary Computer) | 10 м | США, Канада, Мексика, DTM | NAVD88 |

SRTM и NASADEM используют EGM96, Copernicus и ALOS — EGM2008, 3DEP —
NAVD88. В одном проекте используется один набор: смешивать системы высот
нельзя, на границах тайлов появятся ступеньки в несколько метров. ALOS —
это DSM (с растительностью и постройками), 3DEP — настоящий DTM.

Для Copernicus и ALOS атрибуция обязательна, для SRTM, NASADEM и 3DEP
она справочная. В любом случае строка атрибуции выбранного набора
добавляется в макет печати атласа рядом с подписью OSM. Она записывается
в переменную проекта `dem_attribution` и выводится в подписи макета.

При скачивании тайлов SRTM в строке состояния идёт объём и текущая скорость
(`Загрузка рельефа: 15.5 МБ · 1.0 МБ/с`); тайлы, взятые из кэша, в счётчик
не попадают. Растровые наборы (Copernicus, NASADEM, ALOS, 3DEP) читаются
по HTTP Range: целиком многогигабайтные тайлы не качаются, в локальный
GeoTIFF вырезается только окно охвата. Кэш окон лежит в
`<проекты>/qgisxtopo-cache/srtm/cog/<источник>`. Репроецированный DEM также
используется повторно: кэш действителен, пока не изменились охват или
исходные данные рельефа.

Готовый рельеф и контуры высот тоже не пересчитываются заново: результат
сохраняется в кэш (`<проекты>/qgisxtopo-cache/terrain`) и берётся из него,
пока совпадают версия плагина, параметры обработки (шаг и сглаживание
контуров, метод масштабирования) и исходные данные (тайлы DEM, слои воды и
ледников). Изменилась версия плагина или параметры — рельеф считается
заново. В журнале в этом случае появляется строка
`Использован кэш рельефа: повторная обработка не требуется`.

Контуры высот делятся по ледникам: часть изолинии внутри ледника попадает в
слой ледниковых изолиний (в шаблоне он рисуется синим), а обычные изолинии на
площади ледника обрываются — иначе одни и те же линии рисовались бы дважды.

Контуры обрываются и по воде — как по постоянной, так и по пересыхающей
(`intermittent=yes`): по сухому озеру или водохранилищу горизонтали не нужны.
Поэтому изолинии режутся по слоям `water_dissolved` и
`water_intermittent_dissolved` (если растворённого слоя нет — по исходному).
Режутся все изолинии, включая ледниковые: вода отсекается до того, как
контуры делятся на ледниковые и обычные.

Пересыхающая вода на карте рисуется горизонтальными голубыми линиями — так же,
как на тайлах OSM: без заливки и без обводки, цвет прежний. Стиль лежит в
шаблоне проекта: чтобы он применился, данные нужно подготовить заново —
шаблон единственный источник стилей, готовые проекты на ходу не переделываются.

### Вкладка «Проект» (открытый проект)

Когда открыт подготовленный проект, панель переключается на настройки карты:
включение контуров высот (вместе с изолиниями ледников), крутых и равнинных
склонов, затенения рельефа и подписей горных массивов — всё привязано к слоям
проекта. У «Крутых склонов», «Равнинных участков» и «Затенения рельефа» есть
своя шкала прозрачности: она показывает текущее значение слоя и меняет его
сразу, шкала недоступна, пока слой выключен.

Галочки «Кратность» (5, 10, 25, 50, 100, 200, 1000 м) действуют на оба слоя
изолиний — обычных и ледниковых: изолинии ледников рисуются теми же
интервалами, поэтому включение и снятие кратности меняет их одинаково.

У крутых склонов в шаблоне три варианта окраски — для гор, предгорий и
равнин: слои «[TERRAIN] slope (steep) var1…var3» с общей подложкой
`slope_upscaled.tif` и разными цветовыми шкалами. Рядом с галочкой
«Раскр. уклонов» есть кнопка выбора варианта: в
свёрнутом виде она показывает только первую букву выбранного варианта
(«(Г)», «(П)», «(Р)») и крупную стрелку вниз, а по нажатию раскрывается
меню со всеми вариантами.
Одновременно показывается только один из них, остальные скрыты. Кнопка
заблокирована, пока сама опция выключена, а в подсказке к каждому варианту
указан порог уклона
(«Горы — склоны круче 20°», «Предгорья — круче 10°», «Равнины — круче 5°»):
на равнинной карте «Горы» поэтому выглядят почти пустыми. Если включить
другой вариант прямо в дереве слоёв QGIS, выбранным станет он, а шкала
прозрачности перейдёт на него. Вариант сопоставляется с пунктом списка по
полному имени слоя: другие слои с суффиксом «var1» не путаются с уклонами.

«Природоохранные зоны» и их «Подписи» включаются отдельно и по умолчанию
выключены; подписи используют `name`, а при его отсутствии — `name:en` или
`name:de`. При открытии проекта устанавливается
увеличение 150%, а охват карты целиком вписывается в экран. Ниже — блок атласа:
формат и ориентация листа, разрешение (по умолчанию 300 dpi), добавление и удаление
листов, экспорт в PNG и PDF, печать. Кнопка «Изменить» позволяет перетаскивать
рамку листа и менять её размер за угловые маркеры с сохранением пропорций страницы;
листы могут перекрываться. Щелчок выделяет лист оранжевым цветом, после чего
«Удалить» убирает именно его; без выделения удаляется последний лист. Во время
экспорта атласа показывается номер текущего листа и общее количество.

Рядом с галочкой «Контуры высот» есть образец цвета и маленькая кнопка сброса.
Цвет выбирается произвольно и сразу применяется к линиям, штрихам и изолиниям
ледников; подписи получают заметно более тёмный оттенок того же цвета без
обводки. Сброс всегда возвращает цвета из шаблона `automap.qgz` — в том числе
после переоткрытия проекта, в котором был сохранён другой цвет; кнопка сброса
при этом активна, пока цвета проекта отличаются от шаблона. Кнопка «2×» включает
двойную ширину линий изогипс (обычных и ледниковых): включённое состояние
выделено жирной надписью. Ширина хранится в переменной проекта
`isolines_width_mult`, поэтому сохраняется вместе с проектом.

У «Затенения» шкала задаёт прозрачность теней, а не всего слоя:
50% — исходный вид, меньше — тени темнее (0% — непрозрачные), больше —
светлее (100% — без теней). Так тени можно сделать заметно темнее, чем
в шаблоне.

У затенения рельефа два варианта в шаблоне: «[TERRAIN] hillshade var1»
(равнины) и «[TERRAIN] hillshade var2» (горы) на общей подложке
`hillshade_composite.tif`. var1 — светлый фон: ровная поверхность полностью
прозрачна, тени остаются полупрозрачными, а освещённые склоны получают очень
лёгкий серый полутон, поэтому их рельеф не пропадает. var2 — прежняя
отмывка gdaldem с более плотным фоном для гор. Рядом с галочкой «Затенение»
есть кнопка выбора варианта; по умолчанию показывается var1. Как и у крутых
склонов, одновременно виден только один вариант, а выбор переносится по
полному имени слоя.

Штрихи направления вниз на изолиниях (обычных и ледниковых) сдвинуты по
длине линии: фаза считается из идентификатора объекта, поэтому она
одинакова при каждой перерисовке, но у соседних изолиний разная — штрихи
больше не выстраиваются в колонки. Сдвиг не превышает длину линии, поэтому
короткие изолинии не теряют свой штрих. Изменение внесено в сам шаблон
`automap.qgz`: свойство сдвига
лежит в карте свойств символьного слоя — только её читает QGIS, поэтому
изолинии ледников сдвиг фазы получают так же, как обычные.

### Язык интерфейса и подписей на карте

Справа в строке заголовков вкладок есть маленькая кнопка `RU`/`EN`
в рамке, высотой со строку вкладок. По умолчанию интерфейс русский;
кнопка переключает его по кругу (`ru → en → ru`). Выбор сохраняется
в настройках плагина и восстанавливается при следующем запуске QGIS,
независимо от того, открыт проект или нет.

Переключение действует сразу:

* все подписи, кнопки, подсказки, пункты списков и диалоги панели
  переводятся без перезапуска и без потери состояния;
* новые сообщения журнала пишутся на выбранном языке. Уже записанные строки
  остаются на языке, на котором были получены.

Язык подписей на карте выбирается отдельно: отдельной строкой под
инструментами вкладки «Проект» есть подпись «Язык карты», компактный
список (в поле виден короткий код, в раскрытом списке — полные названия)
и галочка «Транслитерация». Пункты по порядку:

* «Местные названия» — только тег `name`;
* «Русский» — `name:ru` → `name` → `name:en`;
* «Английский» — `name:en` → `name`;
* затем ещё 47 языков по алфавиту (немецкий, французский, испанский,
  итальянский, украинский, японский и другие) по той же схеме
  `name:<lang>` → `name`.

Выбор запоминается в настройках плагина. Язык карты задаётся переменными
проекта `name_tag_1..3` и `name_pref_suf_lang`; плагин выставляет их при
открытии проекта и при смене пункта списка и сразу перерисовывает слои.
Переключение не помечает проект изменённым.

Отдельной строкой ниже — список «Детализация» (4 по умолчанию). Это уровень
детализации `level_of_detail`: правила отрисовки шаблона прячут объекты
с порогом выше выбранного. «3 — главное» убирает мелкие родники, тропы
и остановки, «4 — обычный» — как в шаблоне, «5 — подробнее» и «6 — всё»
показывают их больше. В открытом проекте значение ставится в переменную
проекта сразу; для новых проектов плагин записывает его в шаблон при
сборке. Проект, собранный старым шаблоном без этой переменной, при
открытии получает уровень из списка.

Сокращения типовых слов русские при любом языке карты, в том числе при
«Местных названиях»: карта русская, поэтому тип объекта пишется по-русски
независимо от языка названия — «ледник» → «л.», «мыс» → «м.», «брод» →
«бр.», высота подписывается «м». Это касается и подписей, заданных прямо
в шаблоне (`IF(@name_pref_suf_lang IS 'ru', …)`).

При этом русский тип приписывается только названию кириллицей: грузинский
ледник остаётся «შინო», а не «л. შინო». Замена слова типа («ледник» →
«л.») идёт по кириллическим словам, поэтому и она безопасна.

Имена слоёв, которые проходят через GRASS (названия ледников, лесов и
болот), сохраняют исходные имена тегов OSM (`name`, `name:ru`, `@id`): GRASS
при импорте атрибутов переименовывает поля (`name:ru` → `name_ru`), и после
скелета имена возвращаются. Поэтому язык подписей работает и на этих
слоях: например, на леднике с тегом `name:ru` = «ледник Зопхито» при
русском языке подписывается именно это название.

#### Транслитерация и «читаемое» запасное название

Цепочка подписи: `name:xx` (родное название на выбранном языке) → запасное
название → `name:en` (для русского и украинского).

Запасное название — локальное `name`. Оно должно читаться тем, кто смотрит
карту на выбранном языке, поэтому по умолчанию применяется правило
«по читаемости»:

* если письменность названия знакома читателю выбранного языка — название
  остаётся как есть: на русской карте «Москва» остаётся «Москва»;
* иначе название переводится в латиницу: грузинское «საქართველო» на
  русской карте показывается как «Sakartvelo», кириллическое «Москва» на
  английской — как «Moskva».

Знакомые письменности заданы для каждого языка (`READABLE_SCRIPTS` в
`core/transliteration.py`): носитель кириллического языка читает и
кириллицу, и латиницу; носитель грузинского — грузинский и латиницу.
Письменность выбранного языка передаётся в выражение подписи переменной
проекта `name_script`.

Таблицы транслитерации: кириллица (BGN/PCGN), греческий, грузинский,
армянский, иврит, арабский, тайский, корейский (упрощённая романизация).
У китайского и японского словарей нет — их названия остаются как есть.

Галочка «Транслитерация» включает это правило для запасного названия и
работает для всех языков; для «Местных названий» она недоступна — там
запасного варианта нет. Выключенная галочка означает прежнее поведение:
запасное название показывается как есть. Переключение работает на лету:
меняется переменная проекта `name_translit`, подписи перерисовываются сразу.

В выражениях подписей запасное название приводится к читаемому виду
функцией `readable_name()` (`resources/expressions/transliterate.py`).
В шаблоне `automap.qgz` эта ветка
уже прописана. Проекты, подготовленные ранее, получают её при открытии:
плагин дописывает её в выражения подписей слоёв.

Функция `readable_name()` живёт в QGIS, поэтому подписи с ней не рисуются,
если плагин не загружен или был перезагружен без перезапуска QGIS. Чтобы
такого не случилось, плагин при загрузке всегда заново регистрирует свои
выражения, а при открытии проекта проверяет наличие функции: если её нет,
ветка транслитерации из подписей убирается (названия показываются, но без
транслитерации) и в журнал пишется предупреждение.

Переводы интерфейса лежат в `resources/lang/en.json` (ключ — русская
строка, значение — английская; для строк с числами используются шаблоны
`{}`). Чтобы добавить язык интерфейса, достаточно расширить этот каталог
и список `LANGUAGES` в `core/i18n.py`; чтобы добавить язык подписей —
`MAP_LANGUAGES` в `core/map_language.py` (там же — письменность языка
третьим элементом).

#### Сокращение типовых слов

Подписи сокращают слова, обозначающие тип объекта: «урочище Волчьи
Ворота» → «ур. Волчьи Ворота», «ледник Малый» → «л. Мал.», «река
Адегой» → «р. Адегой». Правила лежат в `resources/expressions/` —
по одной функции на тип объекта (`format_water_name()`,
`format_place_name()`, `format_peak_pass_name()`, `format_glacier_name()`
и другие).

Сокращается только слово целиком: «Прудовая», «Ручейка», «Островского»,
«Летниково» и «Ярыженский» остаются как есть, потому что это имена, а не
типы объектов. Слово, составляющее всё название, тоже не сокращается:
посёлок «Остров» подписывается как «Остров», а не «о.». После сокращения
остаётся пробел, лишние пробелы убираются.

Правила проверялись на больших выгрузках OSM (Юг, Кавказ, Урал,
Калининград, Хибины, Москва, Алтай, Якутия, Карелия, Псков, Волга) —
около 130 тысяч названий; тесты: `tests/test_label_abbreviations.py`.

## Ускорение подготовки

Чтение большой выгрузки OpenStreetMap целиком занимает минуты, хотя нужна
только область карты. Поэтому перед чтением область вырезается из выгрузки
инструментом [osmium-tool](https://github.com/osmcode/osmium-tool): вырезка
занимает секунды, а дальше драйвер GDAL работает с маленьким файлом.

| Выгрузка | Без osmium | С osmium |
|----------|-----------|----------|
| Georgia + Северный Кавказ (230 МБ) | 27 с | 10 с |
| Швейцария (550 МБ), область в Грузии | 241 с | 10 с |

Бинарник osmium поставляется вместе с плагином (`vendor/osmium/`, Linux x86_64
и Windows x86_64), ставить его пользователю не нужно. Если бинарник по
каким-то причинам недоступен (например, macOS или ARM), плагин работает как
раньше — медленнее, но без ошибок. Подробности сборки и лицензия (GPL-3):
[vendor/osmium/PROVENANCE.md](vendor/osmium/PROVENANCE.md).

Для Linux поставляется статический бинарник, для Windows — готовая сборка
из conda-forge: `osmium.exe` и пять зависимых DLL лежат рядом, Windows
находит их в каталоге программы.

Вырезается область с запасом (0.3° или 15% от размера области), чтобы линии
и полигоны, пересекающие границу, пришли целиком. Отдельно выбираются
объекты, охватывающие область целиком (горные массивы и хребты): их вершины
лежат далеко за пределами области, и обычная вырезка их не затрагивает.
Эти «покрывающие» файлы читаются целиком, без грубого фильтра GDAL: их
геометрия заведомо вне области, и фильтр отбросил бы их целиком.

## Разработка

```sh
./tools/run_tests.sh                       # тесты
python3 tools/build_plugin.py             # сборка dist/qgis_xtopo-<версия>.zip
python3 tools/build_plugin.py --install   # сборка + обновление профиля QGIS
./tools/run_qgis.sh                       # сборка + установка + запуск QGIS с открытой панелью
```

Шаблон проекта хранится один раз — в корне репозитория (`automap.qgz`).
При сборке он копируется в `resources/automap.qgz` внутрь пакета, поэтому в
исходном дереве дубликата нет, а архив всегда содержит актуальную версию.
Инструментов, которые правят шаблон или готовые проекты, в проекте нет:
стиль задаётся в самом `automap.qgz`, поэтому изменённый стиль попадает на
карту только после переподготовки данных.

Пустые слои (spoil heap, prison, cliff, earth bank gully и другие) вырезаются
из готового проекта, а обращение `overlay_*` к отсутствующему слою обращает
фильтр правила в NULL — объекты пропадают с карты на части масштабов. Поэтому
такие обращения в шаблоне обёрнуты в `try(..., запасное значение)`, а
`core/project.py: patch_overlay_filters` обновляет уже созданные проекты при
открытии.

При чтении PBF грубый фильтр GDAL ставится на все слои, кроме `points`:
фильтр на `points` действует и на остальные слои, из-за чего у отношений с
большим кольцом (границы регионов `admin_level=2/4`, заповедники) пропадают
вершины и они теряются целиком, а линии, пересекающие край области,
приходят обрезанными. Цена решения — чтение `points` без фильтра, примерно
в 4 раза больше времени на чтение выгрузки. Склейка карт через osmium даёт
повторяющиеся id (пограничные объекты входят в обе выгрузки с разными
версиями), и на таком файле драйвер GDAL обрывает чтение — тогда карты
читаются по отдельности, а повторяющиеся объекты отсекаются по `@id`.

Если грубый фильтр драйвера не доставил нужную область (бывает на выгрузках
с битым индексом), файл читается заново целиком. Откат такого чтения
затрагивает только текущий файл: записи уже обработанных файлов остаются
в силе.

### Инструменты в панели плагина

В панели инструментов вкладки «Проект» есть кнопки «Измерить» (меню:
расстояние, площадь, угол, азимут) и «Определить объект». Это штатные
инструменты QGIS: плагин вызывает готовые действия главного окна
(`mActionMeasure`, `mActionMeasureArea`, `mActionMeasureAngle`,
`mActionMeasureBearing`, `mActionIdentify`), поэтому работают ровно так
же, как в самом QGIS. В Python-обёртках QGIS 3.44 классов измерения
нет, а готовые действия — есть. Закрытие окна «Измерение» возвращает
карту в «Перетаскивание карты»: сам QGIS инструмент при этом с холста
не снимает.

### Окно выбора охвата

В окне выбора охвата подписи размеров сторон рамки идут за ней: они
пересчитываются при перемещении карты и прямо во время рисования
рамки, а при перемещении карты с уже нарисованной рамкой подписи
следуют за ней. В правом нижнем углу карты показывается шкала масштаба
с «круглым» расстоянием (1, 2 или 5 × 10ⁿ метров). Esc отменяет выбор и
закрывает окно.

В окне есть поиск места по геокодеру Nominatim: в строку поиска вводится
название (например, «Кисловодск»), результаты показываются списком, а
выбор результата центрирует карту на найденном месте и приближает её
по его границам. Нарисованная рамка при этом сбрасывается — охватом
становится видимая область. Enter в строке поиска запускает поиск, а на
карте — применяет охват и закрывает окно.

Подложка предпросмотра выбирается списком: OpenStreetMap, OpenTopoMap
(топографическая), ArcGIS Topo, Google Satellite и Google Hybrid.
Подложка меняет только карту в окне: в готовую карту она не попадает.

При разметке страниц атласа вдоль границ прямоугольника листа
показывается его размер — так же, как размеры рамки в окне выбора
охвата.

Рядом со списком карт Geofabrik есть кнопка обновления: она помечает
кэш индекса устаревшим, и индекс скачивается заново.

### Проверка полноты данных

`tools/check_pbf_coverage.py` сверяет подготовку с исходными данными:
эталон — osmium вырезает область той же стратегией и тем же запасом, что
и плагин, и раскладывает объекты по слоям тем же движком запросов; затем
сравниваются множества идентификаторов объектов в каждом слое. Подробности
и запуск — в [tools/README.md](tools/README.md).

Оценка времени подготовки в панели («подготовка ≈ …») калибруется по
замерам на выгрузках Малопольши, Грузии, Армении и Юкона: она считает
чтение только области с запасом фильтра, а не всего файла. Прежняя
формула завышала время в 3–8 раз.

### Проверка положения пиков

Ошибочный пик — узел `natural=peak`, поставленный не на гребне, а в долине
или на склоне: на карте он подписывается высотой из `ele_calc` (значение DEM
в точке), но вершины в этом месте нет. Проверяет это
`tools/check_peak_placement.py`: правило, пороги, запуск и разбор
результатов описаны в [tools/README.md](tools/README.md).

При подготовке карты то же правило применяется автоматически
(`core/peak_filter.py`): после рельефа плагин удаляет безымянные пики,
признанные ложными, и заменяет `ele` у остальных безымянных пиков, если
высота расходится с рельефом больше чем на 10 %. Пики с верным положением,
но устаревшей высотой не удаляются. Краткая статистика пишется в журнал.
Чтобы тег `ele` вообще попадал в слой, подготовка PBF использует
`osmconf.ini` без `ele` в `ignore` (`core/pbf_source.py`).

Тесты запускаются с указанием корня репозитория как верхнего уровня

(`unittest discover -s tests -t .`): корень репозитория регистрируется под
именем `qgis_xtopo`, чтобы импорты модулей совпадали с установленным плагином.
