# QGIS-xtopo

Плагин QGIS, который готовит данные OpenStreetMap и рельефа для печатной
топографической карты и открывает их в виде проекта QGIS со стилями
`automap.qgz`.

Никаких Docker, внешних сервисов и ручной подготовки GeoPackage: всё
выполняется прямо в QGIS — от выбора области на карте до экспорта листа
атласа в PNG или PDF.

---

## Возможности

* **Подготовка данных OSM** из Geofabrik (по умолчанию), публичного Overpass
  API, локального PBF/OSM-экстракта, локального Overpass или Overpass по SSH.
* **Подбор карт Geofabrik** по текущему охвату: минимальный набор регионов
  (родительский регион не скачивается, если выбран потомок), проверка
  доступности карт в фоне, скачивание и склейка.
* **Рельеф**: SRTM-тайлы (с кэшем) или локальный каталог DEM, затенение и
  уклоны, контуры высот с выбором кратности (5, 10, 25, 50, 100, 200 м) и
  вырезанием контуров из водных поверхностей, отдельные изолинии по ледникам.
* **Обработка береговой линии** и океана.
* **Параллельная обработка** независимых слоёв, автоматическое удаление
  пустых слоёв из готового проекта.
* **Панель настроек проекта**: включение и выключение слоёв рельефа прямо в
  открытом проекте, привязка к слоям, инструменты «вписать карту в экран» и
  «прокрутка карты».
* **Атлас**: разметка листов прямо на карте, формат и ориентация листа,
  масштабная линейка, номер листа, копирайт OSM, экспорт в PNG/PDF и печать.

---

## Требования

* QGIS 3.28 или новее (проверено на QGIS 3.34).
* GDAL/OGR и Python из состава QGIS — дополнительных установок не требуется.
* Для Overpass API нужен доступ в интернет; для локальных режимов —
  собственный `osm3s_query` или файл `.pbf`/`.osm`.

## Установка

1. Соберите архив (или возьмите готовый из `dist/`):

   ```sh
   python3 tools/build_plugin.py
   ```

2. Установите его в QGIS: **Плагины → Управление и установка плагинов →
   Установить из ZIP**. Либо одной командой в профиль QGIS:

   ```sh
   python3 tools/build_plugin.py --install
   ```

3. Включите плагин «QGIS-xtopo» и откройте его панель
   (меню **Вид → Панели → QGIS-xtopo**).

Корень репозитория одновременно является корнем плагина: при установке
каталог называется `qgis_xtopo`, поэтому в архив файлы кладутся в каталог
`qgis_xtopo/`.

## Использование

### Вкладка «Данные»

| Поле | Назначение |
|------|------------|
| Каталог проектов | куда складывать подготовленные проекты |
| Имя проекта | буквы (латиница и кириллица), цифры и `_ - +` |
| Охват | `lon_min,lat_min,lon_max,lat_max` или ссылка OpenStreetMap; кнопка «Выбрать…» открывает карту и позволяет нарисовать прямоугольник |
| Режим | Geofabrik PBF, публичный Overpass API, локальный PBF, локальный Overpass, Overpass по SSH |

При первом запуске охват пустой. Если нажать «Подготовить данные» без охвата,
плагин сам откроет окно «Выбор охвата карты» (в нём Enter применяет охват и
закрывает окно); если его закрыть, подготовка не
начнётся, а в строке состояния появится «Охват не выбран».

Для режима Geofabrik плагин сам определяет нужные карты по охвату, показывает
их список с родительским регионом и объёмом, а по кнопке «Подготовить данные»
скачивает и склеивает их. Во время загрузки в строке состояния идёт общий
счётчик: процент, скачано/всего, число карт и текущая скорость
(например, `Загрузка карт: 42% (7.7/18.4 МБ) · 0/1 · 3.1 МБ/с`).
Дата индекса Geofabrik показана в заголовке группы «Карты Geofabrik».

Для публичного Overpass сервер проверяется фоновым тестовым запросом, его
доступность показывается в списке.

Режим PBF читает файл в два прохода: сначала грубый фильтр GDAL по области
(с небольшим запасом, чтобы объекты на границе пришли с целой геометрией),
затем точная проверка пересечения с самим охватом — в выход попадают только
нужные объекты. На файле в 500 МБ это сокращает время обработки примерно в
пять раз по сравнению с полным перебором.

### Вкладка «Слои»

Список запросов OSM с кнопками «Все», «Ничего», «По умолчанию».

### Вкладка «Рельеф»

* «Обрабатывать рельеф» — построить затенение, уклоны и контуры.
* «Метод масштабирования» и горизонтальный разделитель.
* «Каталог DEM» — если заполнен, тайлы берутся из него, а «Скачать SRTM…»
  принудительно выключается.
* «Контуры высот» и кратности 5, 10, 25, 50, 100, 200 м: включение одной
  кратности автоматически включает все зависимые (например, 5 м включает
  10/25/50/100/200), несовместимые кратности (200 против 100 и 1000)
  исключаются.
* «Сглаживать контуры».

При скачивании тайлов SRTM в строке состояния идёт объём и текущая скорость
(`Загрузка рельефа: 15.5 МБ · 1.0 МБ/с`); тайлы, взятые из кэша, в счётчик
не попадают.

### Вкладка «Проект» (открытый проект)

Когда открыт подготовленный проект, панель переключается на настройки карты:
включение контуров высот (вместе с изолиниями ледников), крутых и равнинных
склонов, затенения рельефа и подписей горных массивов — всё привязано к слоям
проекта. У «Крутых склонов», «Равнинных участков» и «Затенения рельефа» есть
своя шкала прозрачности: она показывает текущее значение слоя и меняет его
сразу, шкала недоступна, пока слой выключен. Ниже — блок атласа: формат и
ориентация листа, разрешение (по умолчанию 300 dpi), добавление и удаление
листов, экспорт в PNG и PDF, печать.

Слой затенения рельефа не затемняет белый фон карты: на ровных и освещённых
участках растр полностью прозрачен, тень появляется только на склонах и
остаётся полупрозрачной. В шаблоне проекта один слой затенения —
«[TERRAIN] hillshade».

## Структура репозитория

```
qgis-xtopo/            корень = корень плагина QGIS
├── __init__.py        classFactory для QGIS
├── plugin.py          точка входа плагина
├── metadata.txt       метаданные и версия
├── core/              логика без GUI
│   ├── bbox.py        разбор охвата
│   ├── config.py      параметры подготовки
│   ├── geofabrik.py   индекс и подбор карт Geofabrik
│   ├── overpass_*.py  работа с Overpass API
│   ├── pbf_*.py       оценка и разбор PBF
│   ├── pipeline.py    оркестрация подготовки
│   ├── project.py     сборка и открытие проекта QGIS
│   └── terrain.py     рельеф, контуры высот
├── gui/               панель плагина
│   ├── dockwidget.py  вкладки «Данные», «Слои», «Рельеф»
│   ├── projectpanel.py вкладка «Проект», атлас, экспорт
│   └── extentdialog.py выбор охвата на карте
├── resources/         ресурсы плагина
│   ├── automap.qgz    шаблон проекта (копия корневого automap.qgz)
│   ├── queries/       запросы Overpass
│   ├── expressions/   выражения QGIS
│   ├── icons/         пиктограммы стилей
│   └── config.ini     значения по умолчанию
├── tests/             тесты (94 шт.)
├── tools/             сборка и запуск тестов
├── automap.qgz        исходный шаблон проекта (мастер-копия)
├── legacy/            старый Docker-проект, больше не используется
└── dist/              собранные архивы плагина
```

## Разработка

```sh
./tools/run_tests.sh                       # тесты
python3 tools/build_plugin.py             # сборка dist/qgis_xtopo-<версия>.zip
python3 tools/build_plugin.py --install   # сборка + обновление профиля QGIS
```

При сборке исходный шаблон `automap.qgz` копируется в `resources/automap.qgz`,
поэтому править стили нужно в корневом файле, а архив всегда содержит
актуальную версию.

Тесты запускаются с указанием корня репозитория как верхнего уровня
(`unittest discover -s tests -t .`): корень репозитория регистрируется под
именем `qgis_xtopo`, чтобы импорты модулей совпадали с установленным плагином.

## legacy

В каталоге `legacy/` лежит прежняя реализация проекта — Docker-образ, shell-
скрипты подготовки данных, отдельное GUI на Python, профиль QGIS и старые
запросы Overpass. Текущий плагин ничего оттуда не использует: все нужные
ресурсы продублированы в `resources/`. Каталог оставлен как история и не
обновляется.
