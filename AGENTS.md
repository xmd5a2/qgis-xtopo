# AGENTS.md — qgis-xtopo

## Что это

- Плагин QGIS (не приложение и не библиотека), минимум QGIS 3.28. Готовит
  данные OSM и рельефа (SRTM) и собирает проект QGIS из шаблона `automap.qgz`.
  Старый Docker-пайплайн лежит в `legacy/` только для справки.
- Корень репозитория — корень пакета: при установке каталог называется
  `qgis_xtopo`, поэтому импорты в тестах идут как `qgis_xtopo.core...`
  (`tests/__init__.py` регистрирует пакет).
- Плагин самодостаточен: только QGIS и его Python, без pip-зависимостей и
  системных утилит. Исключение — поставляемый `vendor/osmium/`; без него
  плагин обязан работать, только медленнее (`core/osmium_prefilter.py`).

## Команды

```sh
./tools/run_tests.sh                      # все тесты, offscreen, ~20 с
./tools/run_tests.sh tests.test_project   # только выбранный модуль (можно несколько)
python3 tools/build_plugin.py             # dist/qgis_xtopo-<версия>.zip + dist/qgis-xtopo-ready/
python3 tools/build_plugin.py --install   # + установка в профиль QGIS
./tools/run_qgis.sh                       # сборка + установка + QGIS с открытой панелью
WINEPREFIX=~/.cache/wineprefix-inno ./installer/build-installer.sh  # Windows-инсталлятор
QT_QPA_PLATFORM=offscreen python3 tools/check_pbf_coverage.py       # сверка полноты с osmium
```

- После изменения поведения: тесты зелёные → `build_plugin.py --install` →
  `installer/build-installer.sh`. Инсталлятор собирается всегда, даже если
  правка не про Windows: он содержит ту же копию плагина.
- При смене версии правьте `metadata.txt` **и** `#define MyAppVersion`
  в `installer/qgis-xtopo.iss`.
- Тесты — `unittest`. `tools/run_tests.py` запускает каждый модуль отдельным
  процессом: QGIS не переносит два приложения в одном процессе.
  `QT_QPA_PLATFORM=offscreen` уже выставлен. Запускайте имена модулей, а не
  отдельные классы: часть тестов создаёт `QgsApplication` в `setUpClass`, и
  класс, запущенный первым, может упасть на `QFontDatabase`.
- Интеграционные тесты с PBF пропускаются, пока `QGIS_XTOPO_TEST_PBF` не
  указывает на локальный `.pbf`. `check_pbf_coverage.py` дополнительно ждёт
  выгрузки Geofabrik в `~/qgis_projects/qgisxtopo-cache/geofabrik`.
- CI тесты не запускает: workflows собирают только Windows-инсталлятор и
  бинарники osmium.

## Структура и поток данных

- `core/pipeline.py` — оркестрация. Источники OSM (`geofabrik.py`,
  `overpass_*.py`, `sources.py`) → вырезка `osmium_prefilter.py` → чтение
  `pbf_source.py` → раскладка по слоям (`query_recipes.py`,
  `resources/queries/`) → рельеф `terrain.py` → чистка пустых слоёв.
  `core/project.py` собирает проект из шаблона в начале и удаляет пустые слои
  в конце.
- `core/terrain_cache.py` — кэш DEM/изолиний; `core/transliteration.py` +
  `map_language.py` — язык карты; `core/i18n.py` + `resources/lang/en.json` —
  язык интерфейса; `core/expressions.py` — регистрация выражений QGIS;
  `core/measure.py` — размеры рамки; `core/peak_placement.py` — правило
  проверки пиков; `core/peak_filter.py` — его применение к слою `peak`.
- `gui/dockwidget.py` — вкладки «Данные/Слои/Рельеф»; `gui/projectpanel.py` —
  вкладка открытого проекта, атлас и слои.
- **Штатные инструменты QGIS** (измерение, identify) вызываются через `QAction`
  по `objectName`: `mActionMeasure`, `mActionMeasureArea`,
  `mActionMeasureAngle`, `mActionMeasureBearing`, `mActionIdentify`. В
  Python-обёртках QGIS 3.44 классов измерения нет
  (`gui/projectpanel.py: _trigger_qgis_action`).
- **Подписи размеров** — `core/measure.py` по эллипсоиду WGS84; в окне охвата
  они берутся у `MeasuredCanvas.set_frame_provider` при каждой отрисовке.
  Шкала масштаба считается от ширины видимой области, а не от знаменателя
  масштаба (`gui/extentdialog.py: scale_bar`).
- `automap.qgz` лежит только в корне; путь в коде — `core/resources.py:
  template_path()`. При сборке копируется в пакет как
  `resources/automap.qgz`. Рядом не оставлять `*.bak*`.
- `dist/`, `output/`, `installer/payload/`, `__pycache__/`,
  `resources/automap.qgz` — артефакты, не редактировать.

## Ограничения

- **Git**: после каждой законченной feature (не тестовой!) делать коммит с осмысленным комментарием
  на английском. Без явной просьбы не делать `push`, `checkout`, `reset --hard`, `stash`.
- **Стиль — только в `automap.qgz`**. Инструментов правки шаблона и переноса
  стиля в готовые проекты нет (не возвращать `tools/patch_template_*.py`).
  `core/project.py: repair_project` при открытии лишь убирает пустые слои,
  чинит шрифт и оборачивает `overlay_*` в `try(...)`, но стиль не обновляет.
  Изменили стиль — переготовьте данные.
- **Пустые слои** вырезаются при сборке; обращение `overlay_*` к
  отсутствующему слою даёт NULL и скрывает объекты. Поэтому такие фильтры
  обёрнуты в `try(..., запасное значение)` (`patch_overlay_filters`).
- **Панель ≤ 600 px по высоте** — тест `test_dock_is_compact`
  (`tests/test_pipeline_integration.py`). Сжимайте spacing/высоту, а не тест.
- **Строка статуса — `WrappedLabel`, высота не фиксирована**: длинный
  прогресс Geofabrik с ETA переносится и не обрезается. Прогресс
  (`Загрузка карт:`) не проходит через `_short_status`, иначе обрежется
  хвост с расчётным временем.
- **Рабочие данные пользователя** (`~/qgis_projects/...`, кэш Geofabrik) не
  использовать как тестовые полигоны; чтение и offscreen-открытие допустимы.

## Шаблон и стили

- **Варианты крутых склонов**: `[TERRAIN] slope (steep) var1/var2/var3` на
  общей подложке `slope_upscaled.tif`, показывается один. Привязка строго по
  полному имени (`STEEP_VARIANTS`, `LAYER_NAMES` в `gui/projectpanel.py`);
  другие слои с «var1» вариантами не являются, а переименование слоя в
  шаблоне ломает панель. Выбор — кнопка с меню, не выпадающий список: в узкой
  панели он обрезает названия.
- **Варианты отмывки рельефа**: `[TERRAIN] hillshade var1/var2` на общей
  подложке `hillshade_composite.tif`. var1 — светлый фон для равнин:
  прозрачность 0 при значении 190 (плоскость), тени темнее, а освещённые
  склоны получают лёгкий серый полутон, чтобы не терять их рельеф. var2 —
  прежняя отмывка gdaldem для гор. Показывается один слой, по умолчанию
  var1; выбор — кнопка с меню рядом с «Затенением». Подпись сокращена,
  чтобы кнопка помещалась в узкой панели. Привязка по полному
  имени; `[TERRAIN] hillshade` остаётся запасным именем для старых проектов.
  Меняя параметры отмывки, обновляйте точку 190 в шкале var1 и
  `HILLSHADE_STYLE_VERSION`.
- **Фаза штрихов изолиний**: `offsetAlongLine` должен лежать внутри карты
  `properties` блока `data_defined_properties`. Свойство рядом с картой QGIS
  не читает, и штрихи выстраиваются колонками. Проверка —
  `tests/test_template_styles.py`.
- **Изолинии режутся по воде до деления на ледниковые и обычные**
  (`terrain.py: generate_isolines`, `_water_mask_paths`): по
  `water_dissolved` и `water_intermittent_dissolved`, иначе по исходным слоям.
  Тест — `GlacierIsolinesWaterTest`.
- **Треки на 1:50 000+**: в правилах слоя `track` для
  `highway_integrity='3'` должен быть символ в каждом диапазоне масштаба.
  Пропуск этой ветки оставлял треки с таким значением без отрисовки.
  Диапазоны 50k+ дополнительно фильтруются по `@level_of_detail`
  (50–100k ≥3, 100–200k ≥3, 200–300k ≥4, 300k+ ≥5). Проверка —
  `TrackScaleTest`.

## Подписи и язык карты

- Язык карты — переменные проекта. **Пустое значение переменной удаляется**,
  `@name_pref_suf_lang` становится NULL, QGIS не вызывает функцию подписи, и
  названия исчезают. Защита внутри выражений не помогает: QGIS до них не
  доходит.
- `@name_pref_suf_lang` равен `ru` даже при «Местных названиях»: тип объекта
  сокращается по-русски всегда («ледник» → «л.», «брод» → «бр.»).
- `level_of_detail` — переменная, на которой держатся фильтры отрисовки во
  многих слоях (дороги, тропы, родники). Без неё правила ложны. Панель: 3–6,
  по умолчанию 4, ключ `SETTINGS_KEY_DETAIL`; в новый проект попадает через
  `project.py: _set_detail_variable`.
- `pick_name_part` (`core/transliteration.py` +
  `resources/expressions/transliterate.py`): берёт кириллическую часть,
  помеченную языком (`ru: ...`) или скобками с той же строкой другой азбукой;
  скобки-уточнения (`Mersedes Benc (грузовой)`) название не заменяют. Дефис
  внутри слова не делит, тире с пробелами делит. При `script="local"`
  название выводится целиком.
- Русский тип объекта (`л.`, `м.`, `хр.`, `ур.`) приписывается только
  кириллическому названию (`_has_cyrillic` в `resources/expressions/
  format_*.py`). Название из одного слова типа не дополняется префиксом.
  Списки типовых слов у водной и населённой групп должны совпадать.
- Выражения (`readable_name`, `format_place_name`, `pick_name_part`, ...)
  регистрируются `core/expressions.py: load_expressions()`. Если функции нет,
  QGIS не рисует подписи. Доступные функции — `registered_functions()` через
  `QgsExpression.Functions()`; `registeredFunctionNames()` в QGIS нет.
- **Название острова не должно вытесняться пиком**: у подписей островов
  (`island polygon`, `island point names`) `priority=7`, у пиков — `6`.
  Иначе пик занимает место, и имя острова не размещается. Проверка —
  `tests/test_template_styles.py`.

## Источники рельефа

- **Единый список источников — `core/dem_sources.py`.** Ключи: `srtm`
  (по умолчанию), `cop30`, `nasadem`, `alos`, `3dep`, `manual`. Там же
  описание для интерфейса, покрытие, атрибуция и проверка доступности.
- `Config.terrain_source` хранит ключ; `resolved_terrain_source()` понимает
  старые `config.ini` без этого поля (`get_terrain_tiles=true` → `manual`,
  иначе `srtm`). В `config.ini` пишется явный ключ.
- **Доступность проверяется сразу после изменения охвата, в фоне и до
  открытия вкладки «Рельеф»** (`DemAvailabilityWorker` в
  `gui/dockwidget.py`). Наборы без данных для охвата отключаются в списке,
  а выбранный недоступный источник заменяется подходящим.
- **3DEP выбирается автоматически**, если покрывает всю сушу охвата
  (`dem_sources.preferred_source`). Океанские тайлы — те, где нет ни
  ALOS, ни Copernicus, — не мешают выбору; если land-mask не построилась,
  требуется покрытие всех тайлов. Ручной выбор другого источника для
  такого охвата даёт предупреждение (`source_warning`), «Свой каталог»
  не перетирается.
- Для `cop30`/`nasadem`/`alos`/`3dep` доступность и список тайлов берутся
  из STAC Planetary Computer; для SRTM — по широтному покрытию
  −56…60°, ручной каталог доступен всегда.
- Ограничения покрытия: у GLO-30 не опубликованы 25 тайлов (Армения,
  Азербайджан, СЗ Иран, Туркменистан), NASADEM только −56…61°, 3DEP —
  США, Канада и Мексика. Не предлагать эти наборы там, где данных нет.
- Растровые наборы читаются по HTTP Range через `/vsicurl` и сразу
  переводятся в локальное окно EPSG:4326 (`terrain.py: download_cog_dem`).
  Запас вокруг охвата `COG_PADDING = 0.002°`: тайлы Copernicus сдвинуты
  относительно целых градусов, без запаса у края остаётся полоса nodata.
  Окно ограничено `MAX_DEM_PIXELS` (120 млн пикселей); для больших охватов
  разрешение снижается, об этом пишется в журнал.
- Кэш окон — `<проекты>/qgisxtopo-cache/srtm/cog/<источник>`; ключ включает
  охват. Меняя запас, формат окна или источник данных, поднимайте версию
  `v1` в `terrain.py: _cached_cog`, иначе старый кэш отдаст устаревшее.
  Перед загрузкой `terrain_input_dir` очищается, иначе в сборку
  попадут тайлы другого набора.
- **Одна вертикальная система на проект**: SRTM/NASADEM — EGM96,
  Copernicus/ALOS — EGM2008, 3DEP — NAVD88. Смешивать нельзя. ALOS — DSM,
  3DEP — DTM.
- Атрибуция источников пишется в переменную проекта `dem_attribution`;
  подпись макета атласа (рядом с OSM) выводит её через
  `[%if(@dem_attribution ...)%]`. `rewrite_project_archive` получает
  `dem_attribution` из выбранного источника. Рамка подписи — 210 мм: это
  предел переноса длинной строки, но видимый прямоугольник подгоняется
  по тексту (`ProjectPanel._fit_copyright_label` вызывает
  `adjustSizeToText()` при открытии проекта и перед экспортом). Иначе
  белая полоса тянется на все 210 мм.
- Строки доступности в панели короткие (`Availability.message`), полные
  формулировки — в `Availability.detail` и подсказке. Подпись в панели —
  `WrappedLabel`: высота считается по фактической ширине, иначе в узкой
  панели обрезается последняя строка с числом тайлов.
- Верхняя граница охвата не включает тайл, начинающийся ровно на ней:
  `tiles_for_bbox` использует `ceil(max) - 1`.

## Рельеф и кэш

- `terrain_cache.py` переиспользует DEM/изолинии, пока совпадают версия
  плагина (`metadata.txt`), параметры (шаг, сглаживание, ресемплинг) и
  исходные данные. Меняя формат результатов, добавляйте новые файлы в
  `DEM_FILES`/`ISOLINES_FILES`, иначе старый кэш отдаст устаревшее.
- **Отмывка — как `gdaldem hillshade` по умолчанию**: солнце 315°/45°, без
  вертикального преувеличения, плюс 10 % подсветки теней
  (`terrain.py: generate_hillshade_slope`). Многонаправленная отмывка с
  `altitude=70`, `zFactor=2` и примешиванием уклона давала почти белое
  полотно. Меняя параметры, поднимайте `HILLSHADE_STYLE_VERSION` в
  `terrain_cache.py`, иначе кэш вернёт старую картинку. Шкала var1 в шаблоне
  привязана к «плоскому» значению 190: после изменения высоты солнца или
  подсветки теней её нужно сдвинуть.
- Оценка времени в панели (`dockwidget.py: _estimate_seconds`) считается от
  доли области в выгрузке (`pbf_fast.py: extended_ratio`), а не от общего
  числа объектов; прежняя формула завышала в 3–8 раз.

## Драйверы и osmium (частые потери данных)

- **GRASS переименовывает поля**: первый недопустимый символ → `x`, остальные
  → `_` (`name:ru` → `name_ru`, `@id` → `xid`). После `skeleton` имена
  восстанавливает `Pipeline._restore_field_names` (правило
  `_grass_field_name`). Растворение — по `@id`.
- **Порядок углов GDAL**: `SetSpatialFilterRect` принимает
  `(minx, miny, maxx, maxy)`, а `GetEnvelope()` отдаёт
  `(minx, maxx, miny, maxy)`. Не смешивать; отбор полигонов — через
  `terrain.py: _PolygonIndex`.
- **Драйвер OSM читается по кругу**: опрашивать слои по одному объекту в
  порядке `INTERLEAVED_LAYER_ORDER` (`points → lines → multilinestrings →
  multipolygons → other_relations`). Чтение слоя до конца теряет
  мультиполигоны.
- **Замкнутые coastline-way внутри мультиполигона драйвер отдельно не
  отдаёт**: у группы островов остаётся только relation (например,
  `place=archipelago`). Поэтому `resources/queries/island.txt` включает
  архипелаги, иначе острова не попадают в `island.sqlite`, не вычитаются из
  океана и остаются под водой.
- **Фильтр на `points` действует на все слои** и теряет вершины больших
  отношений. Поэтому `_apply_spatial_filter` ставит фильтр на все слои, кроме
  `points`; точная отсечка — при разборе. Цена — примерно в 4 раза больше
  времени на чтение PBF.
- **Склейка osmium даёт повторяющиеся id**: GDAL обрывает чтение.
  `sources.py: prepare_sources` при ошибке читает карты по отдельности,
  дубликаты отсекаются по `@id`.
- **`osmium extract`**: `-b <padded bbox> --strategy=smart -S types=any`;
  запас `padded_bbox` — 0.3° или 15% от области. `smart` не берёт отношения
  вне области, их добирает `tags-filter` по `COVERING_EXPRESSIONS` (горные
  массивы и хребты). Вырезанные области нескольких карт склеиваются
  `osmium merge` **после** вырезки, иначе разорванные границей отношения не
  собрать.
- **Файлы горных массивов читаются без фильтра** (`unfiltered`): их геометрия
  лежит вне области, и фильтр отбросил бы их целиком.
- **Откат чтения** (фильтр не доставил область → файл читается целиком)
  обрезает записи только текущего файла по смещению, а не всех.
- Бинарь в zip теряет бит исполнения — `osmium_tool.py: ensure_executable`;
  имя файла ровно `osmium` (osmium воспринимает его как имя команды).
- Полнота проверяется `tools/check_pbf_coverage.py`: эталон — osmium,
  сравнение множеств `@id`. Известный остаток ~0,06% на границе области;
  увеличение запаса фильтра не помогает.

## Проверка в реальном QGIS

- Offscreen-тесты не покрывают регистрацию плагина и раскладку окон.
- Не трогать работающий QGIS (`pgrep -x qgis.bin`); запускать с временным
  профилем: `qgis --profiles-path /tmp/... --code script.py`.
- Панель открывается при `QGIS_XTOPO_OPEN=1`; показ — по
  `iface.initializationCompleted`, иначе восстановление окон перезапишет
  `show()`.
- Плагин включается секцией `[PythonPlugins]` в `QGIS/QGIS3.ini` профиля
  (не `[Plugins]`). В `qgis.utils` QGIS 3.44 нет `enabled_plugins`.

## Проверка положения пиков OSM

- `tools/check_peak_placement.py` ищет `natural=peak` без названия, стоящие
  не на вершине и не на хребте. Проверяются только пики без тегов `name` и
  `name:xx`; с `ele` и без — две разные категории в отчёте.
- **Источник рельефа выбирается `--dem-source`**: поддерживаются все наборы
  плагина (`srtm`, `cop30`, `nasadem`, `alos`, `3dep`, `manual`). Растровые
  наборы скачиваются через `core.terrain.download_cog_dem` и приводятся к
  сетке 1″ в EPSG:4326, поэтому метрики сравнимы с SRTM. Для `manual` или
  своего файла — `--dem-file`.
- **Для ALOS, Copernicus и NASADEM включается профиль порогов**
  (`SOURCE_THRESHOLD_PROFILES`): их поверхность сдвигает метрики
  относительно SRTM, и базовое правило даёт 6–10 ложных срабатываний на
  95 верных пиках. Профиль поднимает `no_crest_450` (40→80),
  `far_drop` (240→260), `near_max_d` (300→400 у ALOS/Copernicus),
  `summit_far_neighbour` (600→900), `ele_below` (4→4.6) и опускает
  `stream_distance` (200→50). У NASADEM `near_max_d` остаётся 300, а
  первая конъюнкция требует, чтобы вершина была дальше 100 м
  (`valley_summit_min`, аргумент `--valley-summit`). На ручной разметке:
  SRTM 0 ложных / 46 из 49, ALOS 0 / 37, Copernicus 2 / 38,
  NASADEM 1 / 39. `--no-source-profile` возвращает базовое правило;
  `3dep` и `manual` профиль не получают.
- **Правило — ИЛИ конъюнкций**: ошибка отмечается, если сработала хотя бы
  одна пара признаков. Одиночное условие не годится — «нет острого гребня
  в 100 м» срабатывает и на настоящих круглых вершинах.
- **В пайплайне правило применяется автоматически** после рельефа
  (`core/peak_filter.py`): безымянные пики с вердиктом `error` удаляются из
  `peak.sqlite`, у остальных безымянных пиков `ele` заменяется на высоту
  рельефа при расхождении больше 10 %. Конъюнкция 11 (`ele_diff`) при
  удалении отключена: расхождение высоты — повод исправить `ele`, а не
  удалить пик. Для SRTM окна читаются из кэша `.hgt` (та же сетка, что у
  инструмента), для остальных источников — из `merged_dem.tif`. Краткая
  статистика выводится в журнал.
- **`ele` у точек сохраняется только с `osmconf.ini` без `ele` в `ignore`**
  (`pbf_source.ensure_osm_config`): стандартный конфиг GDAL выбрасывает
  тег, и подписи высот не работают.
- Признаки — по выбранному рельефу и высоте из тега OSM `ele`: гребень
  (выпуклость поперёк склона на нескольких масштабах), водораздел (площадь
  водосбора D8), поперечный профиль склона, кольцо вокруг точки, ближайший
  локальный максимум, кривизна, расхождение `ele` и DEM.
- **Рельеф — это SRTM v3 (AWS `elevation-tiles-prod/skadi`), не SRTM1.**
  Кэш плагина и тайлы skadi байт-в-байт одни данные. Завышение DEM в
  Гималаях — свойство самих данных, а не артефакт заполнения пустот.
  Copernicus GLO-30 хуже: разброс расхождения с OSM `ele` −15…+30 % против
  −8…+11 % у SRTM v3. Менять источник DEM смысла нет.
- **Геометрию водных объектов OSM для правила не использовать:** ручьи
  проведены по-разному, признак получается ненадёжным (пользователь так
  решил после того, как метрика расстояния до ручья дала хороший результат
  на одной выборке).
- **Два разных признака «ближайшая вершина»: `summit_*` считается по сырому
  DEM, `near_max_*` — по сглаженному.** В сетке перебора был только
  сглаженный, и грубые пики в пологом рельефе терялись. Оба нужны.
- **В Гималаях DEM завышен на сотни метров** (у 43 % пиков DEM выше OSM
  `ele`): абсолютные пороги в метрах там не работают. Часть признаков
  нормирована на местный рельеф, сверка `ele` с DEM вынесена в отдельный
  признак.
- Пороги перебираются перебором по размеченной вручную выборке: цель —
  ноль ложных срабатываний на «верных» пиках при максимуме пойманных
  «ошибочных». Правку порогов проверять на всей выборке сразу: на одном
  регионе легко поймать лишнее.
- **При поиске конъюнкций важно пересечение, а не каждое условие
  по отдельности.** Одиночное условие, задевающее верные пики, в паре с
  другим может дать ноль ложных. Если отбрасывать такие условия сразу,
  теряется большая часть кандидатов и качество правила падает (на разметке
  95 верных / 49 ошибочных это стоило 3 пойманных пика).
- Переносить правило из настройки в инструмент нужно пошагово: сверить
  значения метрик (инструмент и настройка обязаны считать одинаково) и
  пороги конъюнкций. Один и тот же признак может входить в разные
  конъюнкции с разными порогами — для каждой свой аргумент.
- Шапка CSV и строка должны иметь одинаковое число полей, иначе значения
  разъезжаются по столбцам и отчёт врёт. В `write_reports` стоит проверка.
- `tools/render_peak_review.py` рисует фрагменты карты по CSV, рендер
  параллельный (`--jobs`). `tools/make_peak_map.py` собирает интерактивную
  карту; `--csv` можно указать несколько раз — регионы сводятся на одной
  карте.
- Материалы проверки лежат в `~/qgis_projects/peak_review_<регион>/`,
  размеченные вручную пики — в `~/qgis_projects/peak_review_labels/`
  (каталог `/tmp` очищается, метки там теряются).

## Стиль изменений

- В этом проекте комментарии, docstring'и и сообщения — на русском, как в
  окружающем коде (это переопределяет общее правило про английский).
- UI-строки пишутся по-русски; английский — в `resources/lang/en.json`
  (словарь «русская строка → английская», работает в обе стороны). Уже
  построенные виджеты переводит `gui/translation.py`.
- Тесты добавлять в существующие тематические файлы. Запуск — только через
  `./tools/run_tests.sh`.
- После изменения поведения обновляйте docstring'и и README (разделы
  «Установка» и «Разработка»).
