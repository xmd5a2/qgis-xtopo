# AGENTS.md — qgis-xtopo

Памятка проекта. Подробные правила разложены по файлам `docs/agents/` — перед
правкой соответствующей части прочитайте нужный (указатели в конце).

## Что это

- Плагин QGIS (не приложение и не библиотека), минимум QGIS 3.30. Готовит
  данные OSM и рельефа (SRTM) и собирает проект QGIS из шаблона `automap.qgz`.
  Старый Docker-пайплайн лежит в `legacy/` только для справки.
- Корень репозитория — корень пакета: при установке каталог называется
  `qgis_xtopo`, поэтому импорты в тестах идут как `qgis_xtopo.core...`
  (`tests/__init__.py` регистрирует пакет).
- Плагин самодостаточен: только QGIS и его Python, без pip-зависимостей и
  системных утилит. Исключение — поставляемый `vendor/osmium/`; без него
  плагин обязан работать, только медленнее (`core/osmium_prefilter.py`).
- **Исходники QGIS лежат рядом с проектом** — `~/git/QGIS` на этой
  машине (на другой каталог может называться `~/git/qgis`: регистр зависит
  от файловой системы). Это клон `github.com/qgis/QGIS`, рабочее дерево
  чистое. По нему смотрят код QGIS, при необходимости обновляют —
  `git pull` там делать можно. Ветка `master` — 4.5-dev, а установлен
  QGIS 3.44.7 (на момент проверки), поэтому поведение и номера строк
  сверяйте с тегом `final-3_44_7` (`git show final-3_44_7:путь`), а не с
  master. В upstream ничего не отправляем: QGIS запрещает вклад с помощью
  ИИ (QEP 408), поэтому правки делаем только в своём плагине.

## Команды

```sh
./tools/run_tests.sh                      # все тесты, offscreen, ~1.5 мин
./tools/run_tests.sh tests.test_project   # только выбранный модуль (можно несколько)
python3 tools/build_plugin.py             # dist/qgis_xtopo-<версия>.zip
python3 tools/build_plugin.py --install   # + установка в профиль QGIS
./installer/install-and-run.sh            # последняя сборка из dist/ + запуск QGIS
./tools/run_qgis.sh                       # сборка + установка + QGIS с открытой панелью
WINEPREFIX=~/.cache/wineprefix-inno ./installer/build-installer.sh  # Windows-инсталлятор
QT_QPA_PLATFORM=offscreen python3 tools/check_pbf_coverage.py       # сверка полноты с osmium
```

- После изменения поведения: тесты зелёные → `build_plugin.py --install` →
  `installer/build-installer.sh`. Инсталлятор собирается всегда, даже если
  правка не про Windows: он содержит ту же копию плагина.
- При смене версии правьте `metadata.txt` **и** `#define MyAppVersion`
  в `installer/qgis-xtopo.iss`.
- Тесты — `unittest`. `tools/run_tests.py` запускает каждый модуль отдельным
  процессом: QGIS не переносит два приложения в одном процессе.
  `QT_QPA_PLATFORM=offscreen` уже выставлен. Запускайте имена модулей, а не
  отдельные классы: часть тестов создаёт `QgsApplication` в `setUpClass`, и
  класс, запущенный первым, может упасть на `QFontDatabase`.
  Для разового скрипта вне `unittest` сначала выполните `import tests`: он
  регистрирует корень репозитория как пакет `qgis_xtopo`.
- Интеграционные тесты с PBF пропускаются, пока `QGIS_XTOPO_TEST_PBF` не
  указывает на локальный `.pbf`. `check_pbf_coverage.py` требует выгрузки
  Geofabrik в `~/qgis_projects/qgisxtopo-cache/geofabrik`; участки без
  нужного файла пропускает с сообщением.
- CI тесты не запускает: workflows собирают Windows-инсталлятор и бинарники
  osmium и проверяют установку QGIS через OSGeo4W.

## Структура

- `core/pipeline.py` — оркестрация. Источники OSM (`geofabrik.py`,
  `extracts.py`, `slice_estimate.py`, `overpass_*.py`, `sources.py`) → вырезка
  `osmium_prefilter.py` →
  чтение
  `pbf_source.py` → раскладка по слоям (`query_recipes.py`,
  `resources/queries/`) → рельеф `terrain.py` → чистка пустых слоёв.
  `core/project.py` собирает проект из шаблона в начале и удаляет пустые слои
  в конце. Слои новой сборки пишутся в `.xtopo_stage` внутри каталога проекта
  (`Config.stage_dir`): пути слоёв в проекте относительные, поэтому готовый
  набор подменяет прежний только после успеха, а сбой или отмена оставляют
  прежний проект целым.
- `core/terrain_cache.py` — кэш DEM/изолиний; `core/transliteration.py` +
  `map_language.py` — язык карты; `core/i18n.py` + `resources/lang/en.json` —
  язык интерфейса; `core/expressions.py` — регистрация выражений QGIS;
  `core/measure.py` — размеры рамки; `core/peak_placement.py` — правило
  проверки пиков; `core/peak_filter.py` — его применение к слою `peak`;
  `core/underwater.py` — удаление подводных вершин и вулканов;
  `core/poi_icons.py` — вытеснение значков; `core/label_cache.py` — кэш
  линий подписи; `core/road_packing.py` — слияние и упаковка линий и
  площадей;
  `core/cpu.py` — число потоков; `core/disk_space.py` — свободное место
  на диске и предупреждения о нехватке.
- `gui/dockwidget.py` — вкладки «Данные/Слои/Рельеф»; `gui/projectpanel.py` —
  вкладка открытого проекта, атлас и слои.
- `automap.qgz` лежит только в корне; путь в коде — `core/resources.py:
  template_path()`. При сборке копируется в пакет как `resources/automap.qgz`.
  Рядом не оставлять `*.bak*`.

## Ограничения

- **Git**: после каждой законченной feature (не тестовой!) делать коммит с
  осмысленным комментарием на английском; пометку «gen by AI» ставить в тело
  сообщения, заголовок оставлять без неё. Без явной просьбы не делать `push`,
  `checkout`, `reset --hard`, `stash`. Каждый коммит поднимает версию в
  `metadata.txt` и `installer/qgis-xtopo.iss`: вторая цифра (`0.x.x`) —
  только для крупных фич, третья (`0.0.x`) — для мелких правок,
  документации и остальных изменений.
- **Стиль — только в `automap.qgz`**. Переноса стиля в готовые проекты нет
  (не возвращать `tools/patch_template_*.py`).
  `core/project.py: repair_project` при открытии убирает пустые слои,
  чинит шрифт, оборачивает `overlay_*` в `try(...)`, включает бикубическую
  передискретизацию растров и ограничивает кандидатов линейных подписей
  0.5/см, но стиль не обновляет.
  Изменили стиль — переготовьте данные.
- **Готовый проект не чинится никогда.** Правка вносится в источник
  (шаблон, код, данные), и проект готовится заново. Не дописывать в
  `repair_project` починку готовых проектов и не чинить их иначе.
- **Упакованные слои — `MultiLineString`/`MultiPolygon`.** Шаги
  `pack_roads` и `pack_all` меняют тип дорожных и простых линий на
  `MultiLineString`, площадей и `building` — на `MultiPolygon`, `tree` —
  на `MultiPoint`; слои шаблона, читающие эти файлы, объявляют тот же
  тип. У безымянных групп `building` сохраняются только ключевые поля и
  `area_m2`. Подробности — `docs/agents/drivers.md`.
- **Суша острова может быть только в relation `boundary=land_area`.**
  GDAL не отдаёт way-члены отношений отдельными полигонами, поэтому
  `resources/queries/island.txt` включает `way/relation
  boundary=land_area` наравне с `place=island/islet/archipelago`. Без
  этого Тикехау и Матаива не попадают в `island.sqlite`, не вычитаются
  из океана и остаются под водой. Подробности — `docs/agents/drivers.md`.
- **Океан — только по правой стороне coastline и с достаточной
  плотностью голосов.** Открытый берег, оборванный внутри охвата,
  продлевается по направлению хвоста линии (`_extend_open_lines`), а не
  последнего сегмента: иначе граница выгрузки уводит продолжение в море
  или в сушу. Часть охвата становится водой при `votes >= 1 %` и
  `votes / area >= 10 %` средней плотности; одного числа голосов мало —
  крупная суша с обратными way набирает больше процента. Небольшая бухта
  ниже 1 % принимается при 5 голосах и плотности не ниже 0.5 средней:
  у неё короткий берег, и доля от всех голосов её не находит. Замкнутые
  кольца — острова, они вычитаются. Полностью сухопутный охват океан не
  получает. Подробности и проверка по тайлам OSM —
  `docs/agents/coastline.md`; тесты — `CoastlineIntermediateTest`,
  `LandlockedCoastlineTest`, `CoastlineGeometryTest`.
- **Подсыхание ручьёв — поле `dry_rank`.** `core/stream_drying.py`
  обрабатывает `stream` и `stream_intermittent`, растворяет сеть по
  тегам и скрывает верхнюю часть потока от истока: 250 м на 1:150000,
  700 м — на 1:200000. Обрезка останавливается на T-развилке, но
  продолжается ниже, если все боковые ветви уже удалены. Шаблон
  фильтрует правила по
  `dry_rank` 1/2. Ручьи у родников, выходов из водоёмов и болот
  защищаются: главной линии ставится максимальный ранг, и он
  продолжается вниз до уже видимой ветви. Оторванные полигоном воды
  устья привязываются по направлению линии и наследуют ранг, а выходы
  на берег (`coastline`) защищаются до первой видимой ветви. Стрелки
  направления получают тот же `dry_rank` по OSM `@id`, поэтому не
  висят над исчезнувшим ручьём. `drystream` не участвует. Упаковка
  `stream`/`stream_intermittent` включает `dry_rank` в ключ.
  Подробности — `docs/agents/styles.md`.
- **Подводные вершины определяются по воде, а не по `ele`.** Шаг
  `core/underwater.py` удаляет точки слоёв `peak`, `volcano`,
  `volcano_dirt` и их центроидов, попавшие в `water_dissolved`/`water`;
  наземные пики с отрицательной высотой (`Cinder Hill` -29 м,
  `Mars Hill` -69 м) сохраняются. Вулканы с
  `volcano:type=submarine` удаляются и без маски. Подробности —
  `docs/agents/peaks.md`.
- **Подавление значков POI в шаблоне берётся из поля `hide`.** Правила
  слоёв POI читают готовые пороги, которые считает
  `core/poi_icons.py`; выражений с `overlay_nearest` для подавления
  значков в шаблоне больше нет (в подписи слоя `railway station icons`
  остались два вызова для угла). Шаблон и формат данных должны меняться
  вместе, иначе значки перестанут вытесняться. Фильтры дополнительно
  проверяют, что масштаб попадает в полосы правила (внешние границы
  расширены на 0.5), иначе
  ровно на 1:100000 `NOT (false)` показывает все значки.
- **Мелкие здания скрываются по `@level_of_detail`.** Три правила слоя
  `building` вложены в родительское `lod`, которое сравнивает
  `area_m2` с порогом детализации (6 — все, 5 — 50 м², 4 — 100,
  3 — 175, 2 — 300) и не действует на 1:32 000 и крупнее. `abandoned`
  и `ruins` не фильтруются, `ELSE` остаётся встроенным. Подробности —
  `docs/agents/styles.md`.
- **Мелкие озёра скрываются по `area_geodesic` с 1:400 000.**
  Правила `water` до 1:300 000 не меняются; для 1:400 000–1:1M,
  1:1M–1:3M и 1:3M+ стоят свои пороги по LOD (на 1:3M — 18/12.6/9/5.4/
  3.6 км² для LOD 2…6), LOD 6 не обнуляется. У `water intermittent`
  такие же полосы до 1:3M. Океан не фильтруется: его площадь на порядки
  больше порога. Подписи воды повторяют порог с 1:3M. Подробности —
  `docs/agents/styles.md`, проверка — `WaterLodTest`.
- **Имя речного полигона не дублирует подпись линии.** Шаг
  `core/riverbank_names.py` очищает все поля имён у полигонов
  `water=river`/`waterway=riverbank`, если вариант имени совпадает с
  пересекающей линией `river`/`river_intermittent`. В `water.sqlite`
  сохраняется `waterway` (`field_subset.WATER`). Полигоны
  `natural=water` без речного тега не трогаются: их линия вычитается
  `water_without_riverbanks`, и имя полигона остаётся единственной
  подписью. Подробности — `docs/agents/labels.md`, проверка —
  `RiverbankNameTest`.
- **Подписи слоёв-блокировщиков дорог скрыты**: у слоёв
  `[blocking] highway*` текст и halo прозрачные, а приоритет понижен —
  иначе копия подписи дороги отнимает размещение у настоящей подписи,
  и название дороги выглядит не так, как задумано.
- **Кластеризация точек убрана из шаблона.** 56 слоёв `pointCluster`
  развёрнуты в обычный `RuleRenderer`: точки рисуются отдельными
  значками, кластерный символ не используется. Подробности —
  `docs/agents/styles.md`.
- **Два списка подложек не связаны.** `core/basemap.py: SOURCES` — это
  «Растровая подложка» готового проекта (Google sat, Bing sat, ArcGIS sat,
  OSM), а `gui/extentdialog.py: BASEMAPS` — подложка окна выбора охвата.
  Источник `osm` назван `OSM`, чтобы не путать его с шаблонным слоем
  `OpenStreetMap`, видимость которого хранят `_hide_osm`/`_restore_osm`.
  Точные списки и подсказку проверяют `tests/test_project.py` и
  `tests/test_i18n.py`. Подробности — `docs/agents/styles.md`.
- **Одноразовые скрипты правки шаблона удаляются после применения.**
  Их результат уже в `automap.qgz`, а повторный запуск на изменённом
  шаблоне может испортить стиль. Код удалённых скриптов остаётся в
  истории git; новые разовые правки оформляются так же и удаляются
  после проверки.
- **Пустые слои** вырезаются при сборке; обращение `overlay_*` к отсутствующему
  слою даёт NULL и скрывает объекты. Поэтому такие фильтры обёрнуты в
  `try(..., запасное значение)` (`patch_overlay_filters`).
- **qgs собирается одним проходом правок.** Шаблон — один qgs на десятки
  мегабайт, поэтому блоки `maplayer` ищутся через `str.find`
  (`project._maplayer_spans`), а все правки применяются списком в
  `_apply_edits`; отдельные `str.replace`/срезы копировали бы весь текст.
  Архив пишется с `ARCHIVE_COMPRESSLEVEL = 1`, а `writestr(ZipInfo, ...)`
  требует явного `compresslevel`. Подробности — `docs/agents/runtime.md`.
- **Горячие пути подготовки данных — PBF и значки POI.** В PBF геометрия
  объекта читается один раз, имена и индексы полей кэшируются; пороги
  подавления значков ищутся кольцами с ранней остановкой и минимумом по
  уровням детализации. Подробности — `docs/agents/drivers.md` и
  `docs/agents/labels.md`.
- **Потоки**: перед удалением панели все QThread останавливаются
  (`shutdown_workers`); свой сигнал `finished` в QThread не объявлять.
  Подробности — `docs/agents/ui.md`.
- **`ProcessingRunner` даёт каждому рабочему потоку свой
  `QgsProcessingContext` с отдельным `QgsProject`.** Общий
  `QgsProject.instance()` нельзя: контекст лениво кэширует область
  выражений, и параллельные вызовы гоняются за её пересборку (segfault в
  `createExpressionContextScope`). Проект, созданный в рабочем потоке,
  освобождается там же (`ProcessingRunner.release`): иначе PyQt отложит
  удаление до завершения потока, а там `thread_local` регулярное выражение
  в `QgsProject::writeEntry` уже разрушено — снова segfault.
- **Сеть**: urllib-opener с предохранителем `core/net.py` (ставится в
  `proxy.apply()`), прокси — `core/proxy.py`. Подробности —
  `docs/agents/ui.md`.
- **Пустой план DEM не означает «нет суши».** Если суша в охвате есть, но
  источники не проверены из-за сети (например, SRTM не покрывает широты
  севернее 60°), `download_auto_dem` бросает `TerrainUnavailable`, а
  `prepare_terrain_raster` пишет `WARNING` с `net.last_error()` и собирает
  проект без рельефа. Сообщение «в охвате нет суши» остаётся только при
  пустом `required_tiles`. Совет про прокси добавляется лишь при включённом
  прокси (`net.set_proxy_label` из `proxy.apply`), иначе — только про сеть.
  Подробности — `docs/agents/terrain.md`.
- **Временный профиль для проверки плагина в QGIS**:
  `qgis --profiles-path <dir>` создаёт профили в `<dir>/profiles/default`,
  поэтому `python/plugins` и `QGIS/QGIS3.ini` копируются именно туда, без
  лишнего уровня `QGIS/profiles/default` из домашнего профиля.
- **Настройки проекта нельзя менять при подключении к скрытым окнам QGIS.**
  `QgsMeasureTool`/`QgsMeasureDialog` создаются до загрузки плагинов;
  `QgsProject.setEllipsoid()` пишет запись и помечает проект изменённым,
  поэтому QGIS при старте спрашивает «Сохранить проект?». Эллипсоид
  включается по `QEvent.Show` открытого окна, а `isDirty()` после смены
  восстанавливается (`gui/projectpanel.py`). Подробности —
  `docs/agents/ui.md`.
- **Слои обрабатываются параллельно, по умолчанию 3/4 ядер с потолком 8**
  (`core/cpu.py: cpu_workers`, `Pipeline._worker_count`). На 16 ядрах 12 слоёв
  оказались медленнее восьми: конкуренция за диск и память. На четырёх ядрах
  будет 3 воркера, на восьми — 6. `parallel_workers` в `config.ini` задаёт
  число явно. Остальные CPU-задачи (osmium, проверка пиков) тоже берут 3/4
  ядер; у проверки пиков потолок 4 — больше потоков упираются в GIL и
  работают медленнее. Загрузка окон COG — сетевая, у неё свой фиксированный
  лимит.
- **Параллелизм ограничен доступной памятью** (`core/memory.py`): на 8 ГБ
  одновременно идёт меньше слоёв и процессов `osmium`, на 32 ГБ — потолок по
  ядрам. На машинах до 6 ГБ оценка памяти на слой понижена до 900 МБ, а
  одновременных слоёв не больше трёх: замеры на 4 и 6 ГБ дали выигрыш от
  двух-трёх воркеров при пике процесса меньше 0,83 ГБ, состав слоёв при этом
  не меняется. Linux читает `/proc/meminfo` и лимит cgroup v1/v2, Windows —
  `GlobalMemoryStatusEx`. `parallel_workers` тоже урезается, если запрошено
  больше, чем помещается. `osmium` дополнительно ограничивается по размеру
  исходного PBF: одна крупная карта может занять 4 ГБ. Если оценка пика не
  помещается в доступную память, вырезка пропускается и исходный PBF читает
  GDAL: на 4 ГБ `osmium extract` иначе убивает OOM. Уклон и отмывка
  считаются поблочно (`terrain.py: _transform_raster`): DEM на области
  300 км массив DEM высокого разрешения занимает больше четырёх
  гигабайт. Искусственного укрупнения DEM для уклона, отмывки и
  «Сглаживать контуры» больше нет: всё считается по нативному
  разрешению, включая 3DEP 1/3″ и LiDAR. Сглаживание — нормированная
  свёртка 1-2-1 по окну тайла (`_smooth_dem_values`), временный
  `isolines_dem_x2.tif` не создаётся.
- **Изолинии считаются процессами тайлов, а не потоками.** Контуры,
  вычитание воды и разрезание по ледникам держат GIL: на охвате Гренландии
  один поток дал 24 с на контуры и 105 с на всю стадию, девять потоков —
  48 и 132 с. Сначала процесс считает тайл целиком (контуры, вода, запись
  SQLite), затем разрезание по ледникам идёт частями по 4000 строк
  `ogc_fid` прямо по файлу тайла, а склейка выполняется отдельными
  процессами. На этом охвате стадия занимает около 35 с. Если отдельный
  Python с GDAL не найден, код откатывается на прежний однопроцессный
  путь; `QGIS_XTOPO_NO_ISOLINE_PROCESSES=1` выключает процессы
  принудительно. Число процессов ограничено `ISOLINE_PROCESS_BYTES`
  (1,5 ГБ) и 3/4 ядер.
- **Плотность изолиний — режим отображения, а не данных.**
  `core/isoline_density.py` умножает масштабные пороги renderer- и
  label-правил на 0,5 / 1 / 2 / 4 / 8 и хранит выбор в переменной проекта
  `isolines_density`; уровни и файлы не меняются. Автовыбор по P90 уклона
  выполняется один раз при открытии проекта, если переменной ещё нет
  (горы — «Обычно», предгорья — «Плотно», равнины — «Очень плотно»).
  Режим не заменяет переподготовку: отсутствующие уровни он не создаёт.
  Подробности — `docs/agents/styles.md`.
- **Тяжёлые слои запускаются первыми**: порядок подготовки — по размеру
  исходных данных (`Pipeline._source_size`). Иначе лес и ледники (самые
  долгие слои) стартуют последними и затягивают конец подготовки.
- **Кэш Geofabrik не обновляется сам.** Валидный локальный PBF (`ensure_maps`)
  используется как есть: ежедневная регенерация выгрузок не причина
  перекачивать карты. Свежую выгрузку получают удалением файла из
  `<проекты>/qgisxtopo-cache/geofabrik`.
- **Медленная загрузка PBF заменяет источник один раз за подготовку.**
  Общий сторож `core/download_speed.py` (100 КБ/с за 60 с) считает только
  принятые байты, поэтому ожидание сборки выреза SliceOSM и ответы индексов
  в окно скорости не входят. Запасной источник — Geofabrik, если охват
  покрыт его картами, иначе SliceOSM; из Geofabrik — SliceOSM. После замены
  сторож отключается до конца подготовки, следующая подготовка начинает
  проверку заново. Выбранный в настройках режим не меняется. Подробности —
  `docs/agents/ui.md`.
- **Дописанные участки admin-границ не дублируют существующие.**
  `_admin_border_members` сравнивает way id члена отношения с числовой
  частью `@id`, а из дописываемого участка вычитает объединение уже
  записанных линий (`_line_geometry_union`). Для `admin_level_4` в маску
  входит и `admin_level_2_dissolved`, иначе государственная граница
  возвращается в слой регионов. Подробности —
  `docs/agents/admin-boundaries.md`.
- **Подписи admin-границ идут вдоль кривых.** У `admin level 2 (country
  names)` открытые границы (`label_line`) и у `admin level 4 (region
  names)` линейные правила (`boundary($geometry)` и `label_line`) используют
  `placement="3"` (Curved); площадные названия стран — `placement="7"`
  (PerimeterCurved). Повтор подписей: 160/320 мм у открытых границ
  стран/регионов на мелких масштабах, 400/800 мм у площадных названий.
  Замкнутые контуры отношений нормализуются шагом `orient_rings` (внешнее
  кольцо — против часовой), иначе подпись уходит наружу; `boundary=historic`,
  `boundary=disputed` и `disputed=yes` в admin-слои не попадают.
  Проверки — `OpenBorderAdminLabelTest`, `RegionBoundaryLabelTest`.
  Подробности — `docs/agents/labels.md` и `docs/agents/drivers.md`.
- **Рельеф в pipeline — три стадии.** `prepare_terrain_raster` (скачивание
  тайлов и сборка сырого DEM) не зависит от слоёв и в `run_project`
  работает в потоке `xtopo-terrain` параллельно `Pipeline.run` (стартует
  сразу после создания проекта); ошибки из потока собираются в список и
  всплывают после `join`, отмена проверяется там же, в `finally` поток
  дожидается. `prepare_terrain_relief` (маска воды, уклон, отмывка) ждёт
  воду и идёт после слоёв и береговой линии. `prepare_terrain_isolines`
  ждёт ключ кэша DEM и идёт после рельефа — контуры режутся по воде и
  ледникам (`_water_mask_paths`, `_glacier_polygons` читают `vector_dir`).
  В `run_project` снимок воды и ледников берётся до шага пересечений
  полигонов, а сами изолинии работают в потоке `xtopo-isolines`
  параллельно значкам POI и упаковке слоёв; их join — только перед
  удалением пустых слоёв. Снимок обязателен: `polygon_overlaps`
  переписывает `water_dissolved` и `glacier`, и без него подробный и
  обзорный наборы могли резаться по разным версиям воды.
  `prepare_terrain` остался как последовательная обёртка всех трёх стадий.
  Подготовка источника OSM идёт в потоке `xtopo-sources` параллельно
  созданию проекта: эти стадии друг от друга не зависят, и очередь из них
  удлиняла бы холодную сборку.
- **Единицы высот: подготовка и отображение — разные настройки.**
  `isolines_units` (вкладка «Рельеф», по умолчанию `m`) задаёт шаг
  контуров и поле `ELEV`; в футах шаг переводится в метры для DEM, а
  `ELEV` округляется в целые футы. Единицы входят в
  `isolines_signature`, поэтому метры и футы не делят кэш и не
  смешиваются в каталоге данных. Отображение задаёт `map_units`, единицы
  данных — `map_units_data`; переключение на вкладке «Проект» разрешено в
  обе стороны, меняет только подписи высот и шкалу, изолинии не
  пересчитывает и при расхождении предупреждает. Подробности —
  `docs/agents/terrain.md` и `docs/agents/labels.md`.
- **Рабочие данные пользователя** (`~/qgis_projects/...`, кэш Geofabrik) не
  использовать как тестовые полигоны; чтение и offscreen-открытие допустимы.
- `dist/`, `output/`, `installer/payload/`, `__pycache__/`,
  `resources/automap.qgz` — артефакты, не редактировать.
- **В `dist/` — не больше 5 сборок одного типа.** Устаревшие однотипные
  файлы (`qgis_xtopo-<версия>.zip`, `qgis-xtopo-setup-<версия>.exe`)
  удаляют при новой сборке сами `tools/build_plugin.py` и
  `installer/build-installer.sh`/`.ps1`, чтобы каталог не разрастался.

## Стиль изменений

- В этом проекте комментарии, docstring'и и сообщения — на русском, как в
  окружающем коде (это переопределяет общее правило про английский).
- UI-строки пишутся по-русски; английский — в `resources/lang/en.json`
  (словарь «русская строка → английская», работает в обе стороны). Уже
  построенные виджеты переводит `gui/translation.py`. У подписей
  `QFormLayout` двоеточие входит в текст: для «Единицы высот:» нужен
  отдельный ключ с двоеточием, одного «Единицы высот» мало.
- Сообщения журнала (`progress`, `status`, `_append_log`, `WARNING`/`ERROR`)
  тоже должны быть в `resources/lang/en.json`: `test_i18n` собирает их по
  AST и падает на отсутствующей строке или на дубликате ключа
  (`test_no_duplicate_source_keys`).
- Тесты добавлять в существующие тематические файлы. Запуск — только через
  `./tools/run_tests.sh`.
- После изменения поведения обновляйте docstring'и и README (разделы
  «Установка» и «Разработка»).
