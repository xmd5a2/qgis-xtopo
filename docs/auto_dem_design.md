# Заметки по реализации режима «Автоматически» и источника Sonny DTM

## Проверенные факты (сделаны HTTP-запросы, не догадки)

### Sonny DTM (https://sonny.4lima.de/)
* Лицензия CC BY 4.0, автор «Sonny», атрибуция обязательна.
* Это DTM (bare-earth, LiDAR), а не DSM. Второй настоящий DTM в арсенале
  плагина после 3DEP.
* Данные лежат в **Google Drive**, не на FTP и не на своём сервере:
  `https://drive.google.com/drive/folders/<ID>`.
* Список файлов папки — одним запросом:
  `https://docs.google.com/embeddedfolderview?id=<ID>[&resourcekey=<RK>]#list`
  → `id="entry-<FILEID>"` + `flip-entry-title">N46E009.zip`.
  Обычная страница папки отдаёт только первые 50 элементов.
  Для коллективных папок Европы `resourcekey` обязателен (без него 401).
* Google Drive API v3 без ключа не работает (403 «unregistered callers»).
* Скачивание файла:
  `https://drive.usercontent.google.com/download?id=<ID>&export=download&confirm=t`
  `confirm=t` обязателен — иначе прилетает HTML «Virus scan warning».
* Страновые папки 1″/3″ содержат **ярлыки** (шорткаты) на коллективную
  папку «Европа» — напрямую не качаются. Реальные файлы лежат в
  коллективных папках «Европа 1″» и «Европа 3″».
  Австрия 0,5″ и Швейцария 0,5″ — реальные файлы в своих папках.
* Формат: `.hgt` **без заголовка**, big-endian int16, N×N точек:
  3601 (1″), 7201 (0,5″), 1201 (3″). Имя файла — как у SRTM
  (`N46E009.hgt`), имя задаёт привязку: GDAL открывает `.hgt` только
  при SRTM-имени (файл `s.hgt` не открывается, `N42E044.hgt` — да).
* Драйвер SRTMHGT в GDAL 3.8 понимает только 1201×1201 и 3601×3601.
  Для 7201×7201 нужен VRT с `VRTRawRasterBand` (проверено: данные
  совпадают с numpy, побайтно).
* Вода и пустоты заполнены **нулями**, а не `-32768`.
* Покрытие «Европа 1″»: lat 27…80, lon −32…+34, 1056 тайлов, 4,55 ГБ.
  «Европа 3″»: 1870 тайлов (включая Гренландию), 1,04 ГБ — **не
  используется**: 90 м хуже, чем Copernicus 30 м.
* Разрешение 0,5″ есть только у Австрии и Швейцарии.

### Смешивание источников
* `gdal.Warp` со списком источников: **последний источник выигрывает**
  там, где у него есть данные; nodata более позднего источника
  **не затирает** данные более раннего. Это ровно нужная семантика
  «фон + наложение» (проверено на синтетических растрах).

### Copernicus GLO-30 / 3DEP
* Открытое зеркало Copernicus в AWS (`copernicus-dem-30m`) **неполное**:
  у части тайлов есть только `AUXFILES` и XML, а самого COG `.tif` нет
  (проверено: N40_00_E006_00, N40_00_E007_00 → 404, N47_00_E009_00 → 200).
  Поэтому адрес AWS используется только после проверки HEAD, иначе
  подписывается ссылка из STAC (`elevationeuwest.blob.core.windows.net`).
* 3DEP seamless: коллекция `3dep-seamless`, id вида `n39w079-13`
  (1/3″) и `n39w079-1` (1″); брать надо `-13`.
  Ссылка на файл лежит на `ai4edataeuwest.blob.core.windows.net` и
  требует подписи SAS (`dem_sources.sign_pc`).
* **STAC отвечает нестабильно**: `planetarycomputer.microsoft.com` —
  Azure Front Door, DNS отдаёт один адрес из пула `150.171.109.x`.
  Адрес `150.171.109.53` пингуется и открывает порт 80, но порт 443
  у него не отвечает, поэтому запрос висит до таймаута. Проверено:
  `.101`, `.197`, `.198` отвечают за 0,5 с, `.53` — таймаут.
  Отсюда `_MultiAddressHTTPSConnection`: перебор всех адресов DNS,
  затем A-записи публичных резолверов (Quad9 отдаёт другой узел),
  рабочий адрес запоминается. Результаты проверки кэшируются
  (успех 30 минут, ошибка 2 минуты), а в панели есть кнопка ⟳.

### Вертикальные системы (важно!)
* SRTM/NASADEM — EGM96, Copernicus/ALOS — EGM2008, 3DEP — NAVD88,
  Sonny — «национальные системы, обычно над уровнем моря» (по замерам
  расхождение с EGM96 0…4 м).
* Смешивание 3DEP и Copernicus в одном проекте даёт ступеньку между
  тайлами. Пользователь запросил именно такое смешивание, поэтому
  оно делается, но расхождение вертикальных систем показывается
  пользователю в панели.

## Решение по архитектуре
* «Автоматически» — не набор, а **режим**: источник выбирается по
  тайлам. Приоритет: 3DEP → Sonny DTM → Copernicus GLO-30 (фон) → SRTM.
* Скачивание в режиме «Автоматически» — сначала каждый набор приводится
  к общей сетке мозаики отдельным слоем, затем один `gdal.Warp` по
  списку слоёв (фон внизу, наложение сверху). Источники, которые не
  открылись, пропускаются; если набор не удалось получить целиком, его
  тайлы добирает SRTM.
* Список тайлов Sonny обновляется в фоне при старте плагина и
  кэшируется на диске: `~/.cache/qgis-xtopo/sonny/listings.json`
  (тайлы — в `<проекты>/qgisxtopo-cache/sonny/tiles`).
