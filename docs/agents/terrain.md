# Источники рельефа, мозаика и кэш

Справочная часть `AGENTS.md`. Код — `core/dem_sources.py`, `core/terrain.py`,
`core/sonny.py`, `core/relief.py`, `core/terrain_cache.py`.

## Список источников

- **Единый список — `core/dem_sources.py`.** Ключи: `auto` (по умолчанию),
  `srtm`, `cop30`, `nasadem`, `alos`, `3dep`, `sonny`, `manual`. Там же
  описание для интерфейса, покрытие, атрибуция и проверка доступности.
- `Config.terrain_source` хранит ключ; `resolved_terrain_source()` понимает
  старые `config.ini` без этого поля (`get_terrain_tiles=true` → `manual`, иначе
  `srtm` — это `LEGACY_DEFAULT_SOURCE`). В `config.ini` пишется явный ключ, у
  новых проектов — `auto`.
- **Ограничения покрытия**: у GLO-30 не опубликованы 25 тайлов (Армения,
  Азербайджан, СЗ Иран, Туркменистан), NASADEM только −56…61°, 3DEP — США,
  Канада и Мексика. Не предлагать эти наборы там, где данных нет.
- Для `cop30`/`nasadem`/`alos`/`3dep` доступность и список тайлов берутся из
  STAC Planetary Computer; для SRTM — по широтному покрытию −56…60°, для
  Sonny — по локальному каталогу тайлов, ручной каталог доступен всегда.
- **Одна вертикальная система на проект**: SRTM/NASADEM — EGM96,
  Copernicus/ALOS — EGM2008, 3DEP — NAVD88. Смешивать нельзя. ALOS — DSM,
  3DEP — DTM. Разные системы в мозаике показываются предупреждением
  `mixed_datum_warning`: на границах тайлов возможны ступеньки. Для обычных
  наборов правило прежнее — один набор на проект.

## Проверка доступности

- **Проверяется сразу после изменения охвата, в фоне и до открытия вкладки
  «Рельеф»** (`DemAvailabilityWorker` в `gui/dockwidget.py`). Наборы без данных
  для охвата отключаются в списке, выбранный недоступный источник заменяется
  подходящим. Проверка идёт параллельно по всем наборам
  (`ThreadPoolExecutor` по числу источников), результат кэшируется в
  `_CHECK_CACHE` (успех 30 минут, ошибка 2 минуты); кнопка ⟳ у списка
  источников вызывает `check_availability(force=True)`.
- **Сбой сети не отключает набор**: `Availability(checked=False)` с сообщением
  «не удалось проверить». Для Copernicus при недоступном STAC покрытие
  проверяется прямыми HEAD-запросами к открытому зеркалу AWS
  (`_cop30_file_availability`).
- **STAC отвечает нестабильно**: системный DNS иногда возвращает адрес Azure
  Front Door с закрытым портом 443. `_MultiAddressHTTPSConnection` перебирает
  все адреса из ответа DNS, а если они не открылись — берёт A-записи у
  публичных резолверов (UDP DNS, затем DoH) и пробует их; рабочий адрес
  запоминается на сеанс.
- Строки доступности в панели короткие (`Availability.message`), полные
  формулировки — в `Availability.detail` и подсказке. Подпись в панели —
  `WrappedLabel`: высота считается по фактической ширине, иначе в узкой
  панели обрезается последняя строка с числом тайлов.

## Режим «Автоматически»

- `AUTO_SOURCE` — не набор, а подбор по тайлам 1°×1°. Приоритет
  `AUTO_PRIORITY`: `3dep` → `sonny` → `cop30` (фон) → `srtm`
  (`dem_sources.auto_plan`). В горных регионах между Sonny и Copernicus встаёт
  `alos` (`MOUNTAIN_PRIORITY`): 3DEP и Sonny остаются выше него. Горность
  определяется `core/relief.py` по встроенной сетке
  `resources/data/relief_grid.npz` (1°, минимум и максимум высоты из ETOPO5,
  ~194 КБ; ~0.02 мс на охват, без сети). Охват горный, если перепад высот
  ≥ 800 м хотя бы у 25 % тайлов суши; так Турция, Непал и Кавказ получают
  ALOS. Sonny покрывает Европу (`europe-1s`), поэтому Дания и Польша
  остаются на Sonny, а равнины вне его покрытия (например, степь Казахстана) —
  на Copernicus. Сетка пересобирается `tools/build_relief_grid.py`.
  Принудительного автовыбора 3DEP больше нет: прежняя логика
  `preferred_source` осталась только для предупреждения `source_warning`,
  когда пользователь выбрал набор вручную.
- **3DEP выбирается автоматически**, если покрывает всю сушу охвата
  (`dem_sources.preferred_source`). Суша определяется по Natural Earth из
  ресурсов QGIS (`resources/data/world_map.gpkg`, слой `countries`), а не по
  покрытию ALOS/Copernicus: те публикуют и океанские тайлы с нулевыми
  высотами. Если Natural Earth недоступен, используется покрытие
  ALOS/Copernicus, а при его отсутствии требуется покрытие всех тайлов. Ручной
  выбор другого источника для такого охвата даёт предупреждение
  (`source_warning`), «Свой каталог» не перетирается.

## Сборка мозаики

- `terrain.download_auto_dem`: сначала каждый набор приводится к общей сетке
  отдельным слоем, затем `gdal.Warp` по списку слоёв, где **поздний источник
  перекрывает ранний, а его nodata не затирает ранние данные** (проверено).
  Разрешение мозаики — самый подробный шаг из входящих наборов, который
  влезает в `MAX_DEM_PIXELS`; иначе берётся более грубый шаг.
  `download_sonny_dem` — тот же код с приоритетом `sonny` → `cop30` → `srtm`.
- **Ручной GLO-30 с нехваткой тайлов**: `terrain._download_cop30` проверяет
  покрытие (`auto_coverage`); при полном покрытии идёт обычный
  `download_cog_dem` с кэшем окон, иначе тайлы раскладываются `cop30` →
  `srtm` и собирается мозаика. Сообщение о замене пишется в рантаймовое
  `config.terrain_fallback` (в `config.ini` не сохраняется), панель показывает
  его в `dem_warning`, журнал — отдельной строкой.
- **Растровые наборы читаются по HTTP Range через `/vsicurl`** и сразу
  переводятся в локальное окно EPSG:4326 (`terrain.py: download_cog_dem`).
  Запас вокруг охвата `COG_PADDING = 0.002°`: тайлы Copernicus сдвинуты
  относительно целых градусов, без запаса у края остаётся полоса nodata. Окно
  ограничено `MAX_DEM_PIXELS` (120 млн пикселей); для больших охватов
  разрешение снижается, об этом пишется в журнал.
- **STAC отдаёт тайлы южнее и западнее запроса**: например, на окно 3°×2° —
  20 тайлов вместо 6. Объекты вне окна отбрасываются сразу
  (`terrain._item_overlaps`), иначе их ссылки подписываются и читаются при
  сборке мозаики впустую.
- **Удалённые COG перед мозаикой скачиваются параллельно**
  (`terrain._fetch_cog_windows`, `COG_PREFETCH_WORKERS = 6`): каждый тайл
  отдельным `gdal.Warp` приводится к общей сетке с `dstNodata=-32768`, затем
  финальный warp собирает локальные файлы. Область вне тайла получает nodata,
  поэтому источники не перекрывают друг друга нулями; результат бит-в-бит
  совпадает с прямым warp'ом (проверено на ALOS, 6 тайлов). Число потоков
  здесь не зависит от ядер: это сетевые загрузки. Тайлы грубее
  `MAX_COG_PREFETCH_PIXELS` (3DEP 10 м) остаются на прямом `/vsicurl`, иначе
  предзагрузка читает сотни мегапикселей.
- **Открытое зеркало Copernicus в AWS неполное**: у части тайлов есть только
  AUXFILES и XML. Адрес AWS используется, только если файл реально есть
  (HEAD), иначе ссылка из STAC подписывается (`sign_pc`). Если каталог STAC
  не ответил, покрытие Copernicus считается полным, а неоткрывшиеся тайлы
  пропускаются при сборке слоя.
- **Атрибуция источников пишется в переменную проекта `dem_attribution`**;
  подпись макета атласа (рядом с OSM) выводит её через
  `[%if(@dem_attribution ...)%]`. `rewrite_project_archive` получает
  `dem_attribution` из выбранного источника. Рамка подписи — 210 мм: это
  предел переноса длинной строки, но видимый прямоугольник подгоняется по
  тексту (`ProjectPanel._fit_copyright_label` вызывает `adjustSizeToText()` при
  открытии проекта и перед экспортом). Иначе белая полоса тянется на все
  210 мм.
- Верхняя граница охвата не включает тайл, начинающийся ровно на ней:
  `tiles_for_bbox` использует `ceil(max) - 1`.
- **Журнал называет скачиваемый файл каждого тайла всех источников** —
  «Загрузка тайла рельефа: N46E006.hgt.gz (SRTM v3 (skadi), 30 м)»,
  «…Copernicus_DSM_COG_10_N46_00_E009_00_DEM.tif (Copernicus GLO-30)».
  Иначе параллельные загрузки неотличимы. SRTM — в `download_srtm`
  (terrain.py), растровые наборы — по имени URL в `_cog_sources`, Sonny — в
  `sonny.download_tile`.
- Оценка времени в панели (`dockwidget.py: _estimate_seconds`) считается от
  доли области в выгрузке (`pbf_fast.py: extended_ratio`), а не от общего
  числа объектов; прежняя формула завышала в 3–8 раз.

## Sonny

- **Sonny DTM — один источник из нескольких наборов** (`core/sonny.py`):
  `at-05s`, `ch-05s` (0,5″), `europe-1s`. Набор 3″ (около 90 м) не
  используется: где нет 1″, фоном идёт Copernicus 30 м. Список тайлов берётся
  из Google Drive (`embeddedfolderview`, коллективным папкам нужен
  `resourcekey`), кэшируется на неделю в `~/.cache/qgis-xtopo/sonny` и
  обновляется в фоновом потоке при старте панели. Скачанные тайлы лежат в
  `<проекты>/qgisxtopo-cache/sonny/tiles`.
- Файлы Sonny — zip с одним `.hgt` без заголовка (big-endian int16,
  3601/7201/1201 точек). Драйвер SRTMHGT читает 1201 и 3601, для 7201 нужна
  VRT-обёртка `sonny.hgt_vrt`. Вода и пустоты заполнены нулями, а не
  `-32768`, поэтому нули считаются данными.

## Кэш

- `terrain_cache.py` переиспользует DEM/изолинии, пока совпадают версия
  расчёта (`DEM_VERSION`, `HILLSHADE_STYLE_VERSION`, `ISOLINES_VERSION`),
  параметры (шаг, сглаживание, ресемплинг) и исходные данные. Версия плагина
  в ключ не входит: обновление интерфейса не должно пересчитывать DEM.
  Меняя формат результатов, добавляйте новые файлы в `DEM_FILES`/
  `ISOLINES_FILES` и поднимайте нужную версию, иначе старый кэш отдаст
  устаревшее.
- **Кэш рельефа проверяется до скачивания тайлов** — по подсказке
  `terrain_cache.dem_hint` (версия расчёта, область, источник, параметры; для
  ручного каталога и локальных тайлов — отпечаток файлов). Полный ключ требует
  хеша содержимого тайлов, а подсказка — нет, поэтому повторная подготовка не
  ходит в сеть и не собирает мозаику. Подсказки лежат в
  `terrain_result_cache_dir/dem-hints` (хранится `KEEP_HINTS` штук);
  `store_dem_hint` вызывается после `store_dem`. Если наборы/сообщение о
  замене тайлов должны переживать восстановление из кэша — добавляйте их в
  данные подсказки.
- **Восстановление растров из кэша не копирует лишнего**: файлы, которые уже
  лежат на месте с тем же размером и mtime, пропускаются, а остальные
  связываются с кэшем жёсткой ссылкой. Копия гигабайтных растров стоила
  больше 20 секунд на каждый прогон. Ссылка безопасна, потому что файлы
  удаляются перед каждой подготовкой (`_clean_layers`), и записать в них
  больше нельзя. Исключение — `merged_dem_3857.tif` (+ его `.sha256`):
  его `_clean_layers` сохраняет, и `build_dem` перезаписывает его на месте,
  поэтому он копируется, а не связывается ссылкой (список — в
  `terrain_cache.COPY_ONLY_FILES`). По той же причине `merged_dem.tif` и
  `merged_dem_upscaled.tif` больше не сохраняются при очистке: они всегда
  считаются заново или берутся из кэша.
- **Запись в кэш тоже ссылкой**: `store_dem`/`store_isolines` связывают
  файлы проекта с файлами кэша, копия нужна только для `COPY_ONLY_FILES`.
  Места на диске хватает вдвое: кэш и проект делят одни и те же данные.
- **Отмывка — как `gdaldem hillshade` по умолчанию**: солнце 315°/45°, без
  вертикального преувеличения, плюс 10 % подсветки теней
  (`terrain.py: generate_hillshade_slope`). Многонаправленная отмывка с
  `altitude=70`, `zFactor=2` и примешиванием уклона давала почти белое полотно.
  Меняя параметры, поднимайте `HILLSHADE_STYLE_VERSION` в
  `terrain_cache.py`, иначе кэш вернёт старую картинку. Шкала var1 в шаблоне
  привязана к «плоскому» значению 190: после изменения высоты солнца или
  подсветки теней её нужно сдвинуть.
- Кэш окон COG — `<проекты>/qgisxtopo-cache/srtm/cog/<источник>`; ключ включает
  охват. Меняя запас, формат окна или источник данных, поднимайте версию
  `v1` в `terrain.py: _cached_cog`, иначе старый кэш отдаст устаревшее.
  Перед загрузкой `terrain_input_dir` очищается, иначе в сборку попадут
  тайлы другого набора.
