# Стили шаблона и правила отрисовки

Справочная часть `AGENTS.md`. Стиль живёт только в `automap.qgz`; здесь —
правила, которые его описывают, и проверки в `tests/test_template_styles.py`.

## Порядок слоёв

- **Туннели**: слои `rail tunnel`, `highway main tunnel`, `river tunnel`,
  `stream tunnel`, `canal tunnel` идут подряд сразу под
  `[TERRAIN] isolines glacier` — под всеми линейными слоями (включая
  изолинии), над фоновыми площадными (карьер, ледник, лес). Площадные слои
  середины стека (вода, болото) остаются над туннелями. Проверка —
  `TunnelLayerOrderTest`.
- **Границы admin_level выше воды**: слои `admin level 2 (country borders)` /
  `country names` и группа `admin level 4` (линии и подписи) идут в дереве
  выше группы `water`. Иначе вода закрывает линии границ, а подписи QGIS всё
  равно рисует поверх — они остаются без линии и выглядят висящими в
  воздухе. Проверка — `AdminBoundaryOrderTest`.

## Варианты оформления

- **Крутые склоны**: `[TERRAIN] slope (steep) var1/var2/var3` на общей
  подложке `slope_upscaled.tif`, показывается один. Привязка строго по
  полному имени (`STEEP_VARIANTS`, `LAYER_NAMES` в `gui/projectpanel.py`);
  другие слои с «var1»-вариантами не являются, переименование слоя в
  шаблоне ломает панель. Выбор — кнопка с меню, не выпадающий список: в
  узкой панели он обрезает названия. При открытии проекта вариант ставится
  автоматически по типу рельефа (`core/slope_style.py`): 90-й процентиль
  уклона из `raster/slope_upscaled.tif` — от 30° горы (var1), 12–30°
  предгорья (var2), ниже 12° равнины (var3). Видимость слоёв при этом не
  меняется, ручной выбор пользователя в том же проекте сохраняется. Растр
  читается выборкой 1200×96 пикселей (~10–15 мс): у полосового TIFF каждая
  строка читается целиком, поэтому высоту выборки уменьшать нельзя, ширину
  можно.
- **Отмывка**: `[TERRAIN] hillshade var1/var2` на общей подложке
  `hillshade_composite.tif`. var1 — светлый фон для равнин: прозрачность 0 при
  значении 190 (плоскость), тени темнее, освещённые склоны получают лёгкий
  серый полутон, чтобы не терять рельеф. var2 — прежняя отмывка gdaldem для
  гор. Показывается один слой, по умолчанию var1; выбор — кнопка с меню
  рядом с «Затенением», подпись сокращена, чтобы кнопка помещалась в узкой
  панели. Привязка по полному имени; `[TERRAIN] hillshade` остаётся запасным
  именем для старых проектов. Меняя параметры отмывки, обновляйте точку 190
  в шкале var1 и `HILLSHADE_STYLE_VERSION`.

## Правила по масштабу

- **Треки на 1:50 000+**: в правилах слоя `track` для `highway_integrity='3'`
  должен быть символ в каждом диапазоне масштаба — иначе такие треки не
  рисуются. Диапазоны 50k+ дополнительно фильтруются по `@level_of_detail`
  (50–100k ≥3, 100–200k ≥3, 200–300k ≥4, 300k+ ≥5). Проверка — `TrackScaleTest`.
- **Хутора и отдельные дворы видны до 1:200000**: в слое `places main` ветки
  `hamlet` и `isolated dwelling` (значки и подписи) заканчиваются на
  `scalemaxdenom="200000"`; верхняя граница в QGIS исключающая, поэтому на
  1:200000 их уже нет, на 300k+ правил нет вовсе. Тег `population` ограничение
  не обходит: в ветке `by population` (рендерер и подписи) стоит
  `AND NOT (place IN ('hamlet','isolated_dwelling') AND @map_scale >= 200000)`,
  такие пункты уходят в типовую ветку, где правил на этих масштабах нет.
  Ниже 200k стиль по населению сохраняется. Проверка — `SettlementScaleTest`.
- **Два уровня сервисных дорог**: во всех слоях `highway main*` (включая
  bridge/tunnel и копии для `layer`) обычный `highway=service` без `service=*`
  виден до 1:300000 (100–200k — `@level_of_detail >= 3`, 200–300k — `>= 4`, на
  300k+ правила нет). Дороги с `service=*` скрываются раньше: 50–100k — `>= 4`,
  на 100k+ правил нет; ветка `service driveway`
  (driveway/parking_aisle/alley) имеет те же сроки. Это действует и для
  мостов (`bridge=yes`), и для туннелей (`tunnel=yes`). Где у 100k–300k один и
  тот же символ (туннели, зимние дороги), диапазон не делят на два правила:
  QGIS теряет символ у второго, поэтому LOD проверяется через `@map_scale`
  внутри одного фильтра. Проверка — `ServiceRoadLodTest`.
- **Пересыхающие водотоки на 1:100000 и мельче тоньше постоянных**: в слое
  `stream intermittent` ветка `default` на 100–200k, 200–300k и 300–500k имеет
  ширину 0.12 мм (у `stream` — 0.16). У `river intermittent` и
  `canal intermittent` на 100–300k ширина 0.22 против 0.29, на 300k+ — 0.17
  против 0.23. На более крупных масштабах ширины не меняются. Проверка —
  `IntermittentWaterwayWidthTest`.
- **Подъёмники**: в слоях `aerialway cable car, gondola` и
  `aerialway chair lift` символы 2 (100000–300000) и 3 (300000+) рисуют
  штриховую линию серым `85,85,85`, а центральную линию и стрелки направления
  — светлее, `105,105,105` (на масштабах крупнее 1:100000 линии остаются
  чёрными/тёмно-серыми).
- **`aerialway=goods`**: в слое `aerialway cable car, gondola` правила
  cable_car/gondola отбирают только эти два типа, `goods` рисуется сплошной
  линией `105,105,105` толщиной 0,22/0,20/0,18 мм и только до 1:200000
  (`scalemaxdenom="200000"`, на 300k+ правила нет). Маркеров и стрелок у goods
  нет. Проверка — `AerialwayGoodsStyleTest`.
- **Название острова не должно вытесняться пиком**: у подписей островов
  (`island polygon`, `island point names`) `priority=7`, у пиков — `6`.
  Иначе пик занимает место, и имя острова не размещается. Проверка —
  `tests/test_template_styles.py`.

## Изолинии

- **Фаза штрихов**: `offsetAlongLine` должен лежать внутри карты `properties`
  блока `data_defined_properties`. Свойство рядом с картой QGIS не читает, и
  штрихи выстраиваются колонками. Проверка — `tests/test_template_styles.py`.
- **Изолинии режутся по воде и ледникам растровой маской**
  (`terrain.py: generate_isolines`, `_try_mask_water`, `_try_mask_glaciers`):
  полигоны воды и ледников записываются в копию DEM значением nodata,
  `gdal.ContourGenerate` с `useNoData=1` обрывает контуры у границ ещё при
  генерации. Прежнее векторное срезание (Union всех озёр и `Difference`
  каждой линии) стоило ~74 с на регионе Женевского озера против ~1 с маски.
  Ледниковые изолинии — отдельный проход по растру, очищенному от всего,
  кроме ледников (`keep_only=True`), тоже без векторного деления. Запасной
  векторный путь (`_subtract_water_from_layer`, `_split_isolines_by_glaciers`)
  остался для тайловой нарезки и сбоев маски. Расхождение с прежним кроем —
  до ~2 пикселей DEM у кромки воды.
